C++ pair, tuple e Desestruturação

Às vezes dois ou três valores andam sempre juntos: o nome do aluno e a nota, o produto e a quantidade, o menor e o maior número de uma lista. Criar uma struct para cada combinação dá trabalho. Para esses casos rápidos, o C++ tem o std::pair (par: dois valores) e o std::tuple (tupla: quantos você quiser). E, desde o C++17, uma forma elegante de "desmontar" esses pacotes em variáveis com nome: auto [nome, nota] = …;.

Você vai aprender
  • Criar um std::pair e ler as duas partes com .first e .second; o que faz o std::make_pair.
  • Criar um std::tuple e ler cada parte com std::get<0>, std::get<1>…
  • Usar pair e tuple para uma função devolver vários valores.
  • Desmontar tudo isso com structured bindings (auto [a, b] = …;): com pair, tuple, struct e no for de um std::map.
  • Quando é melhor usar uma struct.

Os programas foram compilados com o g++ 15.2 na máquina fictícia da Ana, na pasta ~/cpp, com g++ -std=c++23 -Wall -Wextra arquivo.cpp -o programa.

A ideia: o envelope com dois papéis

Pense num envelope com duas folhas dentro: a primeira com o nome do aluno, a segunda com a nota. Você entrega o envelope inteiro, e quem recebe abre e tira as duas folhas. Um pair é esse envelope. Um tuple é um envelope que cabe três, quatro, quantas folhas forem necessárias. E as structured bindings são o gesto de abrir o envelope e dar um nome a cada folha.

1. std::pair: dois valores juntos

#include <iostream>
#include <string>
#include <utility>

int main() {
    std::pair<std::string, double> aluno = {"Ana", 9.5};

    std::cout << "Nome: " << aluno.first << '\n';
    std::cout << "Nota: " << aluno.second << '\n';

    aluno.second = 10.0;
    std::cout << aluno.first << " agora tem " << aluno.second << '\n';

    auto outro = std::make_pair(std::string("Bruno"), 7.0);
    std::cout << outro.first << ": " << outro.second << '\n';
}
#include <utility>

Pares sabem se comparar

Dois pares são comparados primeiro pelo first; só em caso de empate, pelo second. Por isso um vetor de pares pode ser ordenado direto com std::sort:

#include <algorithm>
#include <iostream>
#include <string>
#include <utility>
#include <vector>

int main() {
    std::vector<std::pair<std::string, int>> estoque = {
        {"maçã", 12}, {"banana", 30}, {"abacate", 4}, {"banana", 8}
    };

    std::sort(estoque.begin(), estoque.end());
    for (const auto& item : estoque) {
        std::cout << item.first << ": " << item.second << '\n';
    }
}

2. std::tuple: três ou mais valores

O std::tuple (cabeçalho <tuple>) é a generalização do par. Como as partes não têm nome (não existe .third), você as pega pela posição, contando a partir de 0, com std::get<posição>:

#include <iostream>
#include <string>
#include <tuple>

int main() {
    std::tuple<std::string, int, double> produto = {"caderno", 3, 12.9};

    std::cout << "Produto: " << std::get<0>(produto) << '\n';
    std::cout << "Quantidade: " << std::get<1>(produto) << '\n';
    std::cout << "Preço: " << std::get<2>(produto) << '\n';

    std::get<1>(produto) = 5;
    std::cout << "Nova quantidade: " << std::get<1>(produto) << '\n';

    auto outro = std::make_tuple(std::string("caneta"), 10, 2.5);
    std::cout << std::get<0>(outro) << " x" << std::get<1>(outro) << '\n';
}

Por que <0> e não [0], como num vetor? Porque cada posição tem um tipo diferente, e o compilador precisa saber, ao compilar, qual tipo vai sair dali. Por isso a posição tem de ser um número fixo, escrito no código. Uma variável não serve:

int main() {

    for (int i = 0; i < 3; ++i) {
        std::cout << std::get<i>(t) << '\n';

}

3. Devolver vários valores de uma função

Uma função só tem um return e devolve uma coisa só (aula Retorno). Mas essa "coisa" pode ser um par ou uma tupla, e aí cabem vários valores:

#include <iostream>
#include <tuple>
#include <utility>
#include <vector>

std::pair<int, int> menor_e_maior(const std::vector<int>& v) {
    int menor = v[0];
    int maior = v[0];
    for (int x : v) {
        if (x < menor) menor = x;
        if (x > maior) maior = x;
    }
    return {menor, maior};
}

std::tuple<int, int, double> resumo(const std::vector<int>& v) {
    int soma = 0;
    for (int x : v) soma += x;
    double media = static_cast<double>(soma) / v.size();
    return {static_cast<int>(v.size()), soma, media};
}

int main() {
    std::vector<int> notas = {7, 10, 4, 8};

    auto extremos = menor_e_maior(notas);
    std::cout << "Menor: " << extremos.first << ", maior: " << extremos.second << '\n';

    auto r = resumo(notas);
    std::cout << std::get<0>(r) << " notas, soma " << std::get<1>(r)
              << ", média " << std::get<2>(r) << '\n';
}

$ g++ -std=c++23 -Wall -Wextra minmax.cpp -o minmax
$ ./minmax
Menor: 4, maior: 10
4 notas, soma 29, média 7.25

O return {menor, maior}; monta o par direto, porque o compilador já sabe, pela primeira linha da função, que ela devolve um std::pair<int, int>. Funciona, mas repare como o main ficou difícil de ler: extremos.first é o menor? std::get<1>(r) era a soma ou a média? A próxima seção resolve isso.

4. Structured bindings: auto [a, b] = …; C++17

A "desestruturação" (em inglês, structured bindings, "ligações estruturadas") abre o pacote e dá um nome a cada parte, numa linha só:

#include <iostream>
#include <map>
#include <string>
#include <tuple>
#include <utility>
#include <vector>

struct Ponto {
    int x;
    int y;
};

std::pair<int, int> menor_e_maior(const std::vector<int>& v) {
    int menor = v[0], maior = v[0];
    for (int x : v) {
        if (x < menor) menor = x;
        if (x > maior) maior = x;
    }
    return {menor, maior};
}

int main() {
    // 1. com pair
    std::pair<std::string, double> aluno = {"Ana", 9.5};
    auto [nome, nota] = aluno;
    std::cout << nome << " tirou " << nota << '\n';

    // 2. com o retorno de uma função
    auto [menor, maior] = menor_e_maior({7, 10, 4, 8});
    std::cout << "De " << menor << " a " << maior << '\n';

    // 3. com tuple
    std::tuple<std::string, int, double> produto = {"caderno", 3, 12.9};
    auto [item, qtd, preco] = produto;
    std::cout << qtd << "x " << item << " = " << qtd * preco << '\n';

    // 4. com struct
    Ponto p = {3, -2};
    auto [x, y] = p;
    std::cout << "x=" << x << " y=" << y << '\n';

    // 5. com map, no for
    std::map<std::string, int> estoque = {{"banana", 30}, {"maçã", 12}};
    for (const auto& [fruta, quantidade] : estoque) {
        std::cout << fruta << ": " << quantidade << '\n';
    }
}

$ g++ -std=c++23 -Wall -Wextra bindings.cpp -o bindings
$ ./bindings
Ana tirou 9.5
De 4 a 10
3x caderno = 38.7
x=3 y=-2
banana: 30
maçã: 12
auto
Obrigatório: o tipo de cada nome é deduzido sozinho (aula auto). Não dá para escrever std::string [nome, …].
[nome, nota]
Os nomes que você escolhe, um para cada parte, na ordem: o primeiro recebe o first (ou a posição 0, ou o primeiro campo da struct), o segundo recebe o seguinte, e assim por diante.
= aluno;
O pacote a abrir: um pair, uma tuple, uma struct com campos públicos, um std::array ou o retorno de uma função.
const auto& [fruta, quantidade] : estoque
No for de um map, cada elemento é um par chave/valor; aqui ele é aberto direto em dois nomes. O const auto& evita copiar cada par.

Compare o item 5 com a forma antiga, for (const auto& item : estoque) { … item.first … item.second … }. Com nomes, o código "fala" o que está fazendo. Isso é o que torna as structured bindings uma das novidades mais queridas do C++17.

Cópia ou referência?

Com auto [a, b], os nomes se referem a uma cópia do pacote. Para mudar o original, use auto&:

#include <iostream>
#include <map>
#include <string>

int main() {
    std::map<std::string, int> estoque = {{"banana", 30}, {"maçã", 12}};

    for (auto [fruta, qtd] : estoque) {
        qtd = 0;
    }
    std::cout << "Depois da cópia: banana=" << estoque["banana"] << '\n';

    for (auto& [fruta, qtd] : estoque) {
        qtd = 0;
    }
    std::cout << "Depois da referência: banana=" << estoque["banana"] << '\n';
}

$ g++ -std=c++23 -Wall -Wextra bind_ref.cpp -o bind_ref
$ ./bind_ref
Depois da cópia: banana=30           « zerou só a cópia
Depois da referência: banana=0       « zerou o estoque de verdade
FormaQuando usar
auto [a, b] = x;Valores pequenos que você só quer ler (ou uma cópia para mexer à vontade).
const auto& [a, b] = x;Ler sem copiar. O padrão no for de um map ou de um vetor de pares.
auto& [a, b] = x;Mudar o original através dos nomes.

Dois valores, uso rápido e local (o retorno de uma função auxiliar, um par chave/valor)std::pairPronto, compara e ordena sozinho.
Três ou mais valores, uso rápido e localstd::tupleIdem, sem limite de partes.
Os dados aparecem em várias partes do programastructaluno.nota diz muito mais que aluno.second ou std::get<1>(aluno).
A função pode não ter resultado (busca que não acha)std::optionalAula optional e variant.

Com structured bindings, quem usa o pair/tuple ganha nomes. Mas quem lê a assinatura da função std::tuple<int, int, double> resumo(…) continua sem saber o que é cada int. Se a função é importante, uma struct com campos nomeados documenta melhor, e ela também funciona com auto [a, b, c] = …;.

Resumo

  • std::pair<A, B> junta dois valores: .first e .second. Pares se comparam pelo first e desempatam pelo second.
  • std::tuple<A, B, C…> junta quantos você quiser: std::get<posição>(t), com posição fixa a partir de 0.
  • Uma função devolve vários valores devolvendo um pair ou tuple: return {a, b};.
  • auto [a, b] = …; dá nomes às partes de um pair, tuple, struct ou array. const auto& para ler sem copiar; auto& para mudar o original.
  • No for de um map: for (const auto& [chave, valor] : mapa).
  • Com texto, escreva os tipos do pair: sem eles, "Ana" vira const char*.
  • Dados que aparecem no programa todo merecem uma struct com nomes.
