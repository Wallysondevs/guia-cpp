C++ Iteradores

Na aula O que é a STL, você viu que os algoritmos recebem notas.begin() e notas.end(). Essas duas coisas são iteradores: pequenos objetos que apontam um item de um container e sabem andar para o próximo. Nesta aula você vai usá-los com as próprias mãos: pegar o item apontado, avançar, percorrer o container inteiro, e entender o erro mais traiçoeiro deles, o iterador que fica "apontando para o nada" depois de você apagar um item.

Você vai aprender
  • O que é um iterador: um "dedo" apontando um item.
  • begin() e end(), e por que o end() fica depois do último item.
  • *it (o item apontado) e ++it (andar para o próximo).
  • Como percorrer um container com iterador, com auto it e com o tipo escrito por extenso.
  • const_iterator, cbegin() e cend(): o dedo que só lê.
  • Invalidação: o que acontece ao apagar de um vector durante o laço (com o erro real do AddressSanitizer) e o conserto com o retorno do erase.

Todos os programas desta aula foram compilados com o g++ 15.2 na máquina fictícia da Ana, na pasta ~/cpp/it, com g++ -std=c++23 -Wall -Wextra arquivo.cpp -o programa. É bom conhecer std::vector e ter uma ideia de ponteiros (o iterador se parece muito com eles).

A ideia: o dedo na lista de chamada

A professora faz a chamada com o dedo na lista: o dedo começa no primeiro nome, ela lê o nome em que o dedo está, desce o dedo para o próximo, lê, desce… Quando o dedo passa do último nome e chega na margem de baixo da folha, a chamada acabou.

Um iterador é esse dedo:

Na chamadaNo C++Exemplo
Pôr o dedo no primeiro nomebegin(): iterador para o primeiro itemauto it = notas.begin();
Ler o nome onde o dedo está*it: o item apontadostd::cout << *it;
Descer o dedo++it: avança para o próximo item++it;
A margem embaixo do último nomeend(): a posição depois do último itemit != notas.end()

A margem não é um nome: não dá para "ler" a margem. Do mesmo jeito, end() não aponta item nenhum; ele só marca onde a lista acabou. Guarde isso, porque é a fonte de vários erros.

1. begin(), *it e ++it, um passo de cada vez

#include <iostream>
#include <vector>

int main() {
    std::vector<int> notas{7, 9, 4, 10};

    auto it = notas.begin();
    std::cout << *it << '\n';

    ++it;
    std::cout << *it << '\n';

    ++it;
    ++it;
    std::cout << *it << '\n';

    ++it;
    if (it == notas.end()) {
        std::cout << "chegou no fim\n";
    }
}
auto it = notas.begin();
Cria o iterador it (nome tradicional, de iterator) apontando o primeiro item. O auto deixa o compilador escrever o tipo, que é comprido (seção 3).
*it
"O item para onde it aponta". O * é o mesmo dos ponteiros: lê-se "o conteúdo de".
++it;
Avança o dedo um item. Prefira ++it a it++ com iteradores: fazem o mesmo aqui, e o ++it nunca precisa guardar uma cópia (aula ++ e --).
it == notas.end()
Compara dois iteradores: "o dedo chegou na margem?". Iteradores do mesmo container podem ser comparados com == e !=.
$ g++ -std=c++23 -Wall -Wextra dedo.cpp -o dedo
$ ./dedo

9
10                       « dois ++ pularam o 4 e pararam no 10
chegou no fim

2. O end() fica depois do último

E se você tentar ler o end(), como se fosse um item?

    std::vector<int> notas{7, 9, 4, 10};
    auto it = notas.end();

E o último item?

O último item é o anterior ao end(): *(notas.end() - 1), ou, bem mais legível, notas.back(). E nunca leia *notas.begin() num vetor vazio: nele, begin() == end(), e o "primeiro item" não existe.

3. Percorrer o container inteiro

Juntando as peças, o laço clássico com iterador:

#include <iostream>
#include <vector>

int main() {
    std::vector<int> notas{7, 9, 4, 10};

    for (auto it = notas.begin(); it != notas.end(); ++it) {
        std::cout << *it << ' ';
    }
    std::cout << '\n';

    for (auto it = notas.begin(); it != notas.end(); ++it) {
        *it = *it + 1;
    }

    for (std::vector<int>::iterator it = notas.begin(); it != notas.end(); ++it) {
        std::cout << *it << ' ';
    }
    std::cout << '\n';
}
Parte do forO que faz
auto it = notas.begin()Começa com o dedo no primeiro item.
it != notas.end()Continua enquanto o dedo não chegou na margem. Use !=, não <: nem todo iterador sabe fazer < (os da std::list não sabem).
++itDepois de cada volta, desce o dedo.
*it = *it + 1;Pelo iterador também se escreve: cada nota ganha um ponto, no próprio vetor.
std::vector<int>::iteratorO tipo verdadeiro do it, escrito por extenso: "o iterador de um std::vector<int>". É o que o auto economiza.
$ g++ -std=c++23 -Wall -Wextra percorrer.cpp -o percorrer
$ ./percorrer
7 9 4 10
8 10 5 11

E o for de intervalo?

O for (int n : notas) da aula range-for é esse mesmo laço, escrito pelo compilador: por baixo, ele chama begin(), end(), !=, ++ e *. Então quando usar cada um?

Laço com iteradorfor (auto it = …; it != …; ++it)Quando você precisa do iterador em si: para apagar (seção 5), para saber a posição, para começar no meio, para andar de trás para frente.
Laço com índicefor (std::size_t i = 0; i < notas.size(); ++i)Só em vector, array e deque, quando o número da posição importa.

Iteradores devolvidos pelos algoritmos

Muitos algoritmos devolvem um iterador. O std::find devolve o dedo apontando o item achado, ou o end() se não achou. E existe o dedo que anda ao contrário: rbegin() (o último item) e rend() (antes do primeiro).

#include <algorithm>
#include <iostream>
#include <vector>

int main() {
    std::vector<int> notas{7, 9, 4, 10};

    auto pos = std::find(notas.begin(), notas.end(), 4);
    if (pos != notas.end()) {
        std::cout << "achei o " << *pos << " na posição "
                  << pos - notas.begin() << '\n';
    }

    auto nada = std::find(notas.begin(), notas.end(), 5);
    if (nada == notas.end()) {
        std::cout << "5 não está na lista\n";
    }

    for (auto it = notas.rbegin(); it != notas.rend(); ++it) {
        std::cout << *it << ' ';
    }
    std::cout << '\n';
}

$ g++ -std=c++23 -Wall -Wextra achar.cpp -o achar
$ ./achar
achei o 4 na posição 2
5 não está na lista
10 4 9 7

pos - notas.begin() é "quantos passos do começo até o dedo": a posição. Essa conta (e it + 3, para pular três) só existe nos iteradores de vector, array, deque e string, que podem pular direto para qualquer lugar. Nos outros containers, use std::next(it, 3) e std::distance(a, b), do cabeçalho <iterator>. Sempre confira != end() antes de usar *pos: se o find não achou, pos é o end(), e você já viu o que acontece ao ler o end().

4. O dedo que só lê: const_iterator, cbegin() e cend()

Quando você só quer ler, use cbegin() e cend() (o c é de const). Eles devolvem um const_iterator, um iterador que não deixa mudar o item. Se você tentar, o compilador recusa:

#include <iostream>
#include <vector>

int main() {
    std::vector<int> notas{7, 9, 4, 10};

    for (auto it = notas.cbegin(); it != notas.cend(); ++it) {
        *it = 0;
    }
}

$ g++ -std=c++23 -Wall -Wextra constante.cpp -o constante
constante.cpp: In function ‘int main()’:
constante.cpp:8:13: error: assignment of read-only location ‘it.__gnu_cxx::__normal_iterator<const int*, std::vector<int> >::operator*()’
    8 |         *it = 0;
      |         ~~~~^~~

"Atribuição a um local somente leitura". No meio do nome comprido, repare em const int*: por dentro, esse iterador é um ponteiro para int constante (aula const com Ponteiros). No editor do guia, o Clang diz cannot assign to return value because function 'operator*' returns a const value.

Regra prática: se o laço só lê, use cbegin()/cend(). Assim, se alguém escrever *it = … por engano, o compilador avisa.

O que aconteceu, volta a volta

Quando o erase apaga um item, ele empurra os seguintes uma casa para a esquerda, para não deixar buraco. O iterador it, que apontava o item apagado, passa a ser inválido: oficialmente, ele não aponta mais nada que se possa usar. Na prática, ele fica parado na mesma casa, que agora tem o próximo item. Aí o ++it do for pula esse item:

  1. {7, 3, 4, 10, 2}, dedo no 7: fica. ++it → dedo no 3.
  2. 3 < 5: erase. Vira {7, 4, 10, 2}; o dedo, parado na casa 1, agora vê o 4. O ++it pula para o 10: o 4 nunca foi testado.
  3. 10: fica. ++it → dedo no 2.
  4. 2 < 5: erase. Vira {7, 4, 10}; o dedo, na casa 3, agora está exatamente no end(). O ++it o leva para depois do end().
  5. O teste it != notas.end() continua verdadeiro (o dedo passou da margem sem parar nela), e o *it lê fora do vetor: a falha de segmentação.

O conserto: o erase devolve o próximo

O erase devolve um iterador novo e válido, apontando o item que veio depois do apagado. Use esse retorno, e só avance o dedo quando não apagar:

#include <iostream>
#include <vector>

int main() {
    std::vector<int> notas{7, 3, 4, 10, 2};

    for (auto it = notas.begin(); it != notas.end(); ) {
        if (*it < 5) {
            it = notas.erase(it);
        } else {
            ++it;
        }
    }

    for (int n : notas) {
        std::cout << n << ' ';
    }
    std::cout << '\n';
}
for (auto it = …; it != notas.end(); )
Repare: a terceira parte do for está vazia. O dedo não avança sozinho; quem decide é o corpo.
it = notas.erase(it);
Apaga e já põe o dedo no próximo item (ou no end(), se apagou o último). Nada é pulado.
else { ++it; }
Só avança quando o item fica.
$ g++ -std=c++23 -Wall -Wextra apagar-certo.cpp -o apagar-certo
$ ./apagar-certo
7 10
O jeito mais curto C++20

Para "apagar todos os itens que…", o C++20 tem uma função pronta: std::erase_if(notas, [](int n) { return n < 5; });. Ela faz o laço certo por você. O [](int n) { … } é uma lambda. Para apagar um valor exato: std::erase(notas, 3);. O laço com it = erase(it) continua útil quando, além de apagar, você precisa fazer outra coisa com cada item.

O que mais invalida iteradores

Não é só o erase. Quando um vector cresce além do espaço reservado (por exemplo, num push_back), ele se muda para um bloco de memória maior e devolve o antigo. Todo iterador que apontava para o bloco antigo fica apontando para memória devolvida. Um laço que faz push_back no mesmo vetor que percorre leva o AddressSanitizer a acusar outro erro, heap-use-after-free ("uso do heap depois de liberado"):

Regra de bolso: se o laço muda o tamanho do container, desconfie dos iteradores. Os outros containers têm regras próprias (na std::list, por exemplo, apagar um item só invalida o iterador dele); cada aula de container conta as suas.

Quando dá errado

Falha de segmentação / heap-buffer-overflow num laço que apaga

O que significa: você usou um iterador depois de apagar o item dele (o ++it do for depois de um erase(it)).

Como consertar: it = v.erase(it); e avance só no else. Ou use std::erase_if.

Um número estranho ao ler *v.end(), ou attempt to dereference a past-the-end iterator

O que significa: você leu o end(), que não é um item. Acontece também quando o std::find não acha e você usa o resultado sem conferir.

Como consertar: confira if (pos != v.end()) antes de *pos. Para o último item, use v.back(). Em testes, compile com -D_GLIBCXX_DEBUG.

error: assignment of read-only location

O que significa: você tentou mudar um item por um const_iterator (de cbegin() ou de um container const).

Como consertar: se a mudança é intencional, use begin() num container que não seja const. Se não é, o compilador acabou de achar um erro para você.

Comparar iteradores de containers diferentes

O que significa: for (auto it = a.begin(); it != b.end(); ++it), com a e b diferentes: o dedo nunca encontra a margem de outra folha. Compila e dá comportamento indefinido.

Como consertar: o begin() e o end() têm que ser do mesmo container.

            ++it;
        }
    }

    for (const auto& item : compras) {
        std::cout << item << ' ';
    }
    std::cout << '\n';
}

Resumo

  • Um iterador é um dedo que aponta um item de um container. *it lê (ou muda) o item; ++it avança.
  • begin() aponta o primeiro item; end() aponta a posição depois do último, que não é item. Nunca leia *end().
  • O laço: for (auto it = c.begin(); it != c.end(); ++it). O for de intervalo faz isso por você e é o padrão.
  • cbegin()/cend() dão um const_iterator, que só lê.
  • Apagar ou inserir num vector invalida iteradores. Ao apagar num laço: it = c.erase(it); e ++it só no else. Ou std::erase_if C++20.
  • -D_GLIBCXX_DEBUG e -fsanitize=address transformam esses erros silenciosos em mensagens claras.
