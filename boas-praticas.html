C++ Boas Práticas

O C++ deixa você fazer quase tudo, inclusive muita coisa errada sem reclamar. Um programa pode compilar, rodar e mostrar um número absurdo, ou funcionar no seu computador e quebrar no de outra pessoa. As boas práticas são hábitos que evitam esses problemas antes que eles apareçam. Esta página junta todas as que o guia ensinou num checklist comentado e termina com um programa "antes × depois": um código cheio de problemas, os avisos reais do compilador e a versão consertada, mudança por mudança.

Você vai aprender
  • Os 12 itens do checklist de um bom código C++, cada um com o porquê.
  • Como usar os avisos do compilador (-Wall -Wextra) e o -Werror a seu favor.
  • Por que using namespace std; pode quebrar um programa, com o erro real.
  • Como os sanitizers encontram o erro que o compilador não viu.
  • Como refatorar (melhorar sem mudar o que faz) um programa ruim, passo a passo.

Todos os programas foram compilados com o g++ 15.2 na máquina fictícia da Ana (usuária ana, computador notebook), na pasta ~/cpp/boas. Cada item do checklist tem uma aula própria; aqui você vê todos juntos e aprende a usá-los como rotina.

A ideia: o checklist do piloto

Antes de decolar, todo piloto de avião, por mais experiente que seja, segue um checklist: combustível, portas, flaps. Não é porque ele esqueceu como se pilota. É porque, numa rotina repetida mil vezes, um item esquecido custa caro, e o checklist torna o esquecimento quase impossível.

Programar é parecido. Você sabe o que é uma variável sem valor inicial, mas num programa de 300 linhas, às 23h, ela passa. O checklist abaixo é a sua lista antes de "decolar" (entregar o programa):

1. Compile com -Wall -Wextra (e -Werror em projetos)

O compilador percebe muita coisa suspeita, mas só avisa se você pedir. -Wall (de warnings: all, "todos os avisos", que na verdade são os mais importantes) e -Wextra ("avisos extras") ligam os avisos que todo programador deveria ver. A aula Avisos (-Wall -Wextra) explica cada um.

Este programa soma as notas da Ana. Ele compila e mostra a resposta certa, mas tem dois problemas:

#include <iostream>
#include <vector>

int main() {
    std::vector<int> notas{7, 9, 10};
    int soma = 0;
    int maior;
    for (int i = 0; i < notas.size(); i++) {
        soma += notas[i];
    }
    std::cout << "Soma: " << soma << '\n';
}

comparison of integer expressions of different signedness
"Comparação de inteiros com sinais diferentes": o i é int (pode ser negativo) e o notas.size() é unsigned (nunca negativo). Comparar os dois pode dar resultados estranhos com números negativos (veja Inteiros). O conserto mais simples é nem usar índice: um range-for.

"Variável não usada": você criou maior e esqueceu. Às vezes é sobra; às vezes é sinal de que faltou um pedaço do programa.

Um aviso não impede o programa de ser criado. Por isso é fácil ignorá-los, e em pouco tempo um projeto tem 200 avisos e ninguém lê mais nenhum. A solução dos projetos sérios é o -Werror ("avisos viram erros"): com ele, qualquer aviso impede a compilação. Você vai vê-lo em ação no programa antes × depois.

A regra de ouro: zero avisos

Trate todo aviso como um erro que ainda não aconteceu. Leia, entenda e conserte. Um programa com zero avisos tem uma vantagem escondida: quando aparecer um aviso novo, você vai notá-lo na hora.

Missão: rode e veja os dois avisos (o editor usa o Clang, que escreve as mensagens de outro jeito, mas os avisos são os mesmos). Depois conserte o programa para compilar com zero avisos: apague a variável que sobrou e troque o for com índice por um for (int nota : notas).

#include <iostream>
#include <vector>

int main() {
    std::vector<int> notas{7, 9, 10};
    int soma = 0;
    int maior;
    for (int i = 0; i < notas.size(); i++) {
        soma += notas[i];
    }
    std::cout << "Soma: " << soma << '\n';
}

#include <iostream>
#include <vector>

int main() {
    std::vector<int> notas{7, 9, 10};
    int soma = 0;
    for (int nota : notas) {
        soma += nota;
    }
    std::cout << "Soma: " << soma << '\n';
}

2. Inicialize toda variável

Uma variável local sem valor inicial, como int total;, não começa com zero: ela começa com o que estiver naquele pedaço da memória, um número "lixo". Usar esse valor é comportamento indefinido: o programa pode mostrar 0, mostrar -1192551482 ou fazer coisa pior. O mais traiçoeiro é que, às vezes, o lixo é zero por acaso e o programa parece certo.

int total;              // ruim: valor lixo
int total = 0;          // bom
double preco{};         // bom: as chaves vazias valem zero
std::string nome;       // ok: string e vector começam vazios sozinhos

Dentro de uma struct, dê um valor padrão a cada campo (double preco = 0.0;), como você viu em Structs.

3. Prefira std::vector, std::string e std::array a arrays crus

Um array cru (int notas[5];) não sabe o próprio tamanho, não cresce e deixa você ler a posição 5, 50 ou 5000 sem reclamar. As alternativas da biblioteca padrão resolvem isso:

Em vez deUsePor quê
int notas[5];std::array<int, 5> notas{};Tamanho fixo, mas sabe o tamanho (notas.size()) e funciona com range-for e algoritmos. Aula: std::array.
int* v = new int[n];std::vector<int> v(n);Cresce, libera a memória sozinho. Aula: std::vector.
char nome[50];std::string nome;Cabe qualquer tamanho, sem estourar. Aula: Strings.

4. Ponteiros inteligentes em vez de new/delete

Todo new precisa de exatamente um delete, do tipo certo (new[] pede delete[]), no momento certo, mesmo se uma função terminar no meio. É fácil errar. Os ponteiros inteligentes fazem o delete sozinhos:

Produto* p = new Produto{"maçã", 2.5};      // ruim: e o delete?
delete p;

auto p = std::make_unique<Produto>("maçã", 2.5);   // bom: liberado sozinho

Na prática, quase nunca você precisa nem disso: um std::vector<Produto> guarda os produtos e cuida da memória. A regra é: se você escreveu new, pergunte se um container ou um make_unique resolve.

5. RAII: deixe os objetos cuidarem dos recursos

RAII é a sigla de Resource Acquisition Is Initialization ("adquirir um recurso é inicializar um objeto"). O nome é feio, a ideia é simples: quem abre, fecha sozinho. Um std::ifstream abre o arquivo quando é criado e fecha quando sai de escopo; um std::vector pede memória quando é criado e devolve quando sai de escopo. Você não precisa lembrar de nada.

void ler_lista() {
    std::ifstream arquivo("lista.txt");   // abre
    std::string linha;
    while (std::getline(arquivo, linha)) {
        // ...
    }
}                                          // fecha sozinho aqui, mesmo se houver um return no meio

Os ponteiros inteligentes do item 4 são RAII para memória. A aula Destrutores e RAII mostra como escrever as suas próprias classes assim.

6. const sempre que puder

Se um valor não deve mudar, diga isso ao compilador com const (aula Constantes). Se alguém tentar mudar (inclusive você, daqui a um mês), o programa não compila:

const double taxa = 0.05;
const std::vector<std::string> categorias{"fruta", "limpeza"};

Além de proteger, o const é documentação: quem lê sabe na hora que aquele valor é fixo. Nos métodos de classe, const diz "este método só lê o objeto".

7. const& para objetos grandes

Quando você passa um std::vector ou uma std::string para uma função "por valor", o C++ faz uma cópia inteira. Com mil produtos, são mil produtos copiados a cada chamada. Passar por referência constante (const&) entrega o original, só para leitura, sem copiar nada (aula Por Valor × Por Referência):

double total(std::vector<Produto> estoque);          // copia tudo
double total(const std::vector<Produto>& estoque);   // só olha, sem copiar

Para tipos pequenos (int, double, char, bool), passe por valor: copiar um número é mais barato que criar uma referência.

8. enum class no lugar de enum

O enum antigo vira int sem avisar e espalha os nomes pelo programa inteiro (FRUTA passa a ser um nome solto). O enum class fica fechado no próprio nome: Categoria::fruta, e não se mistura com números (aula Enums).

enum Categoria { FRUTA, LIMPEZA };            // antigo: FRUTA + 1 compila
enum class Categoria { fruta, limpeza };      // moderno: Categoria::fruta + 1 não compila

9. Evite using namespace std; (e nunca em headers)

A linha using namespace std; "despeja" todos os nomes da biblioteca padrão no seu programa, para você escrever cout em vez de std::cout. Parece prático, mas a biblioteca tem milhares de nomes, e alguns são palavras comuns: count, size, distance, max. Veja o que acontece quando a Ana cria uma variável count (contagem):

#include <iostream>
using namespace std;

int count = 0;

int main() {
    count++;
    cout << count << '\n';

10. Funções pequenas, nomes claros

Compare estas duas assinaturas:

double f(vector<Produto> v, int x);
double valor_do_estoque(const std::vector<Produto>& estoque);

A segunda dispensa comentário: você sabe o que ela faz, o que recebe e que não muda nada. Duas regras práticas:

  • Uma função, uma tarefa. Se para descrever o que ela faz você precisa de "e" ("lê o arquivo e calcula o total e mostra"), divida em três (aula Funções). Uma função que cabe na tela inteira é um bom limite.
  • Nomes que dizem o que a coisa é. total_vendas, não tv; quantidade, não q. A exceção são contadores de laço curtos (i). Veja as regras de nomes em Nomes de Variáveis.

11. Sanitizers nos testes

Alguns erros o compilador não consegue ver, porque só acontecem na hora de rodar: ler fora de um array, usar memória já liberada, estourar um int. Os sanitizers ("higienizadores") são verificações que o g++ coloca dentro do programa: ele fica mais lento, mas para no primeiro erro e diz a linha exata. Use-os sempre que testar:

$ g++ -std=c++23 -Wall -Wextra -g -fsanitize=address,undefined programa.cpp -o programa

Você vai ver um deles pegando um erro real no programa abaixo. A aula Sanitizers explica cada tipo e como ler o relatório.

12. Formatação automática (clang-format)

Onde vai a chave? Quatro espaços ou dois? Em vez de decidir na mão, os projetos usam um formatador: o mais comum em C++ é o clang-format, da mesma família do Clang. Ele reescreve o arquivo seguindo regras guardadas num arquivo .clang-format na pasta do projeto, e as IDEs (veja Editores e IDEs) podem rodá-lo toda vez que você salva. O guia só cita a ferramenta: o importante é que o projeto inteiro tenha um estilo, qualquer que seja.

O programa antes × depois

Agora o checklist em ação. Este é o controle de estoque da lojinha da Ana, escrito "do jeito rápido". Ele deveria mostrar o valor do estoque, o total de vendas da semana e quantos produtos estão zerados:

#include <iostream>
#include <string>
#include <vector>
using namespace std;

enum Categoria { FRUTA, LIMPEZA };

struct Produto {
    string nome;
    double preco;
    int qtd;
    Categoria cat;
};

double f(vector<Produto> v, int x) {
    double t;
    for (int i = 0; i < v.size(); i++)
        t += v[i].preco * v[i].qtd;
    return t;
}

int main() {
    vector<Produto> estoque;
    estoque.push_back({"maçã", 2.5, 40, FRUTA});
    estoque.push_back({"sabão", 8.9, 10, LIMPEZA});
    estoque.push_back({"pera", 3.0, 0, FRUTA});

    int* vendas = new int[3];
    vendas[0] = 5; vendas[1] = 2; vendas[2] = 7;
    int total_vendas = 0;
    for (int i = 0; i <= 3; i++)
        total_vendas += vendas[i];
    delete vendas;

    int zerados;
    for (int i = 0; i < estoque.size(); i++)
        if (estoque[i].qtd = 0) zerados++;

    cout << "Valor do estoque: " << f(estoque, 1) << endl;
    cout << "Vendas: " << total_vendas << endl;
    cout << "Produtos zerados: " << zerados << endl;
}

As respostas certas seriam: valor 189 (2,5 × 40 + 8,9 × 10 + 3 × 0), vendas 14 e um produto zerado. Primeiro, a Ana compila sem avisos:

Quando dá errado

"cc1plus: all warnings being treated as errors"

Você (ou o Makefile/CMakeLists.txt do projeto) está usando -Werror, e o código tem pelo menos um aviso. O programa não foi criado.

Como consertar: leia cada linha com error: e o nome entre colchetes ([-Werror=unused-parameter] = o aviso -Wunused-parameter) e conserte o código. Não tire o -Werror para "fazer passar": ele existe exatamente para isso.

"reference to ‘…’ is ambiguous"

Um nome seu bateu com um nome da biblioteca padrão, quase sempre por causa de um using namespace std; (item 9).

Como consertar: apague o using namespace std; e escreva std::, ou dê outro nome à sua variável (contador em vez de count).

"No meu computador funciona"

Um programa que dá a resposta certa num computador e errada em outro, ou certa hoje e errada amanhã, quase sempre tem uma variável sem valor inicial ou uma leitura fora do array: exatamente o t, o zerados e o vendas[3] do programa "antes". O resultado depende do lixo que estava na memória.

Como consertar: compile com -Wall -Wextra -O2 (para os avisos de "may be used uninitialized") e rode com -fsanitize=address,undefined. Veja Comportamento Indefinido.

Resumo

  • Compile sempre com -Wall -Wextra e busque zero avisos; em projetos, -Werror garante isso. Alguns avisos só aparecem com -O2.
  • Inicialize tudo. Variável sem valor tem lixo, e lixo às vezes parece certo.
  • std::vector, std::array, std::string e ponteiros inteligentes no lugar de arrays crus e new/delete. RAII: quem abre, fecha sozinho.
  • const sempre que puder; const& para objetos grandes; enum class no lugar de enum.
  • Nada de using namespace std; em headers; nos .cpp, prefira std::.
  • Funções pequenas com nomes que dizem o que fazem.
  • Teste com -fsanitize=address,undefined: ele encontra o que o compilador não vê. Formate com clang-format.
