C++ optional e variant C++17

A lojinha da Ana tem uma função que devolve o preço de um produto. E se o produto não existir? Devolver 0 mente ("é de graça?"); devolver -1 é um código secreto que alguém vai esquecer de conferir. O C++17 trouxe uma resposta honesta: std::optional, uma caixa que pode estar vazia. Na mesma leva veio o std::variant, uma caixa que guarda um tipo ou outro (um número ou um texto, por exemplo). E o C++23 juntou as duas ideias no std::expected: "um resultado ou o motivo do erro".

Você vai aprender
  • Devolver "talvez um valor" com std::optional e std::nullopt.
  • Conferir e ler: has_value(), if (opt), value(), *opt e value_or(…).
  • O que acontece quando você lê uma caixa vazia: std::bad_optional_access (o erro real).
  • Guardar um tipo ou outro com std::variant: std::holds_alternative, std::get e o erro std::bad_variant_access.
  • Tratar todos os tipos de uma vez com std::visit (o básico).
  • Conhecer o std::expected C++23.

Os programas foram compilados com o g++ 15.2 na máquina fictícia da Ana, na pasta ~/cpp, com g++ -std=c++23 -Wall -Wextra arquivo.cpp -o programa. Alguns exemplos usam try e catch, da aula Exceções.

A ideia: a caixa que pode estar vazia, e a caixa de duas formas

  • optional é como a caixinha de correio da Ana: ou tem uma carta, ou está vazia. Antes de ler a carta, ela olha se tem alguma.
  • variant é como um pote com tampa onde cabe ou açúcar ou sal, nunca os dois. Antes de usar, ela confere a etiqueta para saber o que tem dentro.

1. std::optional: talvez um valor

#include <iostream>
#include <optional>
#include <string>

std::optional<double> preco_de(const std::string& produto) {
    if (produto == "pão") return 0.75;
    if (produto == "leite") return 5.49;
    return std::nullopt;
}

int main() {
    std::optional<double> p1 = preco_de("leite");
    std::optional<double> p2 = preco_de("caviar");

    std::cout << std::boolalpha;
    std::cout << "leite tem preço? " << p1.has_value() << '\n';
    std::cout << "caviar tem preço? " << p2.has_value() << '\n';

    if (p1.has_value()) {
        std::cout << "Leite: R$ " << p1.value() << '\n';
    }
    if (p1) {
        std::cout << "Leite (com *): R$ " << *p1 << '\n';
    }
    if (!p2) {
        std::cout << "Caviar: não vendemos\n";
    }

    std::cout << "Caviar ou 0: " << p2.value_or(0.0) << '\n';
}

std::optional<double>
"Talvez um double." É o tipo de retorno da função.
return 0.75;
Com valor: o double entra na caixa sozinho.
return std::nullopt;
Sem valor: devolve a caixa vazia (null option, "opção nula").
p1.has_value()
"Tem valor?" Responde true ou false.
if (p1)
Atalho para a mesma pergunta: o optional vira true quando tem valor. if (!p2) = "se está vazio".
p1.value()
Pega o valor. Se a caixa estiver vazia, lança uma exceção (seção seguinte).
*p1
Também pega o valor, sem conferir nada. Use só depois de ter conferido.
p2.value_or(0.0)
"O valor, ou então 0.0": nunca falha, porque sempre há uma resposta.

A grande vantagem aparece em quem lê a função: o tipo std::optional<double> já avisa, na assinatura, "posso não ter resposta". Com um double comum e o código secreto -1, nada obriga quem chama a se lembrar disso.

Experimente: rode e veja os dois resultados. Depois acrescente um terceiro produto na função (por exemplo, "café" a 18.90) e busque por ele. Por fim, troque o value_or(0.0) por value_or(-1.0) e veja a diferença.

#include <iostream>
#include <optional>
#include <string>

std::optional<double> preco_de(const std::string& produto) {
    if (produto == "pão") return 0.75;
    if (produto == "leite") return 5.49;
    return std::nullopt;
}

int main() {
    for (std::string produto : {"pão", "chocolate"}) {
        auto preco = preco_de(produto);
        if (preco) {
            std::cout << produto << ": R$ " << *preco << '\n';
        } else {
            std::cout << produto << ": não vendemos\n";
        }
    }
    std::cout << "Sem conferir: " << preco_de("chocolate").value_or(0.0) << '\n';
}

Ler uma caixa vazia: std::bad_optional_access

O value() confere se há valor. Se não há, ele lança uma exceção do tipo std::bad_optional_access ("acesso ruim ao optional"). Se ninguém a capturar, o programa termina na hora:

#include <iostream>
#include <optional>

int main() {
    std::optional<int> idade;
    std::cout << "Antes\n";
    std::cout << idade.value() << '\n';
    std::cout << "Depois\n";
}

Como toda exceção, ela pode ser capturada com try/catch (aula Exceções):

#include <iostream>
#include <optional>

int main() {
    std::optional<int> idade;
    try {
        std::cout << idade.value() << '\n';
    } catch (const std::bad_optional_access& e) {
        std::cout << "Erro: " << e.what() << '\n';
    }
}

$ g++ -std=c++23 -Wall -Wextra value_catch.cpp -o value_catch
$ ./value_catch

Mas o normal é nem chegar aí: confira com if (opt) antes, ou use value_or. E o *idade numa caixa vazia? Ele não confere nada: é comportamento indefinido. Sem otimização, o g++ 15 ainda pega o erro com uma asserção:

Engaged = "ocupado": a biblioteca conferiu "a caixa está ocupada?" e a resposta foi não. Com -O2 essa conferência some, e o programa mostraria lixo sem reclamar.

2. std::variant: um tipo ou outro

Um std::variant<int, std::string> guarda em cada momento um int ou uma std::string. Ele sempre sabe qual dos dois tem dentro:

#include <iostream>
#include <string>
#include <variant>

int main() {
    std::variant<int, std::string> resposta = 42;

    std::cout << std::boolalpha;
    std::cout << "É int? " << std::holds_alternative<int>(resposta) << '\n';
    std::cout << "Valor: " << std::get<int>(resposta) << '\n';
    std::cout << "Índice: " << resposta.index() << '\n';

    resposta = std::string("não sei");
    std::cout << "É string? " << std::holds_alternative<std::string>(resposta) << '\n';
    std::cout << "Valor: " << std::get<std::string>(resposta) << '\n';
    std::cout << "Índice: " << resposta.index() << '\n';
}

$ g++ -std=c++23 -Wall -Wextra variante.cpp -o variante
$ ./variante

Valor: 42
Índice: 0                            « int é o 1º tipo da lista (posição 0)

Índice: 1                            « string é o 2º (posição 1)

A lista de tipos possíveis, chamados de alternativas.
= 42;
Agora guarda um int. Atribuir outro valor troca o tipo: depois de resposta = std::string("não sei"); ele guarda uma string, e o 42 foi jogado fora.
std::holds_alternative<int>(resposta)
"Está guardando um int?" (holds = "segura", "contém").
std::get<int>(resposta)
Pega o valor como int. Se o que está guardado for de outro tipo, lança uma exceção (veja abaixo).
resposta.index()
A posição, na lista, do tipo guardado agora.

Repare que se escreveu std::string("não sei") e não só "não sei". Escrever o tipo deixa claro para o leitor (e para o compilador) qual alternativa você quer.

Pedir o tipo errado: std::bad_variant_access

#include <iostream>
#include <string>
#include <variant>

int main() {
    std::variant<int, std::string> resposta = std::string("não sei");
    std::cout << std::get<int>(resposta) << '\n';
}

$ g++ -std=c++23 -Wall -Wextra get_errado.cpp -o get_errado
$ ./get_errado
terminate called after throwing an instance of 'std::bad_variant_access'
  what():  std::get: wrong index for variant
Abortado                   (imagem do núcleo gravada) ./get_errado

Wrong index for variant = "índice errado para o variant": você pediu o int (posição 0), mas o que está lá é a string (posição 1). Com try/catch (const std::bad_variant_access& e), o programa mostraria Erro: std::get: wrong index for variant e continuaria. O jeito tranquilo é perguntar antes:

#include <iostream>
#include <string>
#include <variant>

void mostrar(const std::variant<int, std::string>& r) {
    if (std::holds_alternative<int>(r)) {
        std::cout << "Número: " << std::get<int>(r) << '\n';
    } else {
        std::cout << "Texto: " << std::get<std::string>(r) << '\n';
    }
}

int main() {
    mostrar(42);
    mostrar(std::string("não sei"));
}

$ g++ -std=c++23 -Wall -Wextra resposta.cpp -o resposta
$ ./resposta
Número: 42
Texto: não sei

std::visit: uma função para todos os tipos (o básico)

Quando há muitas alternativas, uma cadeia de if (holds_alternative…) fica longa. O std::visit ("visitar") chama uma função com o valor que estiver guardado, seja do tipo que for. A função mais simples para isso é uma lambda com parâmetro auto, que aceita qualquer tipo:

#include <iostream>
#include <string>
#include <variant>
#include <vector>

int main() {
    std::vector<std::variant<int, double, std::string>> celulas = {
        10, 3.5, std::string("Ana"), 7
    };

    for (const auto& c : celulas) {
        std::visit([](const auto& valor) {
            std::cout << "[" << valor << "] ";
        }, c);
    }
    std::cout << '\n';
}

$ g++ -std=c++23 -Wall -Wextra visitar.cpp -o visitar
$ ./visitar
[10] [3.5] [Ana] [7]

Imagine as células de uma planilha: cada uma tem um número inteiro, um número com vírgula ou um texto. O std::visit recebe a lambda e a célula c, olha qual tipo está guardado e chama a lambda com ele. Aqui funcionou porque o cout << sabe mostrar os três tipos. Tratar cada tipo de um jeito diferente dentro do visit exige técnicas de templates (if constexpr, citado em constexpr); por enquanto, para tratamentos diferentes, use o holds_alternative.

3. std::expected: um resultado ou o motivo do erro C++23

O optional diz "não achei", mas não diz por quê. O std::expected<T, E> ("esperado") guarda ou o resultado esperado (T) ou um erro (E), que pode ser uma mensagem. É uma alternativa às exceções para erros que acontecem com frequência, como um texto digitado errado:

#include <expected>
#include <iostream>
#include <string>

std::expected<int, std::string> idade_de(const std::string& texto) {
    if (texto.empty()) {
        return std::unexpected("texto vazio");
    }
    int idade = 0;
    for (char c : texto) {
        if (c < '0' || c > '9') {
            return std::unexpected("não é número: " + texto);
        }
        idade = idade * 10 + (c - '0');
    }
    return idade;
}

int main() {
    for (std::string t : {"29", "abc", ""}) {
        auto r = idade_de(t);
        if (r.has_value()) {
            std::cout << "Idade: " << r.value() << '\n';
        } else {
            std::cout << "Erro: " << r.error() << '\n';
        }
    }
}

$ g++ -std=c++23 -Wall -Wextra esperado.cpp -o esperado
$ ./esperado

Erro: texto vazio

"Espero um int; se der errado, você recebe uma std::string explicando."

Como no optional, mais o error() para ler o motivo.

Por ser recente, você vai ver pouco expected em código antigo; em projetos novos, ele é cada vez mais comum. E os ponteiros nulos?

Em código antigo, "talvez não exista" era feito com um ponteiro que podia ser nullptr (aula nullptr). Para devolver um valor, o optional é mais seguro: não há memória para gerenciar e o tipo diz claramente que pode estar vazio.

Quando dá errado

terminate called after throwing an instance of 'std::bad_optional_access'

O que significa: o programa chamou .value() num optional vazio e ninguém capturou a exceção.

Como consertar: confira com if (opt)/has_value() antes, use value_or(padrão), ou capture com catch (const std::bad_optional_access&).

terminate called after throwing an instance of 'std::bad_variant_access' / what(): std::get: wrong index for variant

O que significa: std::get<T> pediu um tipo diferente do que está guardado.

Como consertar: pergunte antes com std::holds_alternative<T>, ou use std::visit.

Resumo

  • std::optional<T>: um T ou nada. Devolva std::nullopt para "nada".
  • Confira com if (opt) ou has_value(); leia com *opt (depois de conferir), value() (lança std::bad_optional_access se vazio) ou value_or(padrão).
  • std::variant<A, B>: um A ou um B. Pergunte com std::holds_alternative<A>; leia com std::get<A> (lança std::bad_variant_access se for o outro).
  • std::visit(lambda, v) trata o valor guardado, qualquer que seja o tipo.
  • std::expected<T, E> (C++23): o resultado ou o motivo do erro, com std::unexpected e error().
  • Os três deixam claro, no tipo, o que pode acontecer, em vez de códigos secretos como -1.
