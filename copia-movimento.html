C++ Cópia e Movimento

Quando você escreve int b = a;, o C++ copia um número. Fácil. Mas o que acontece em Caderno b = a;, quando a é um objeto de uma classe sua? Quem faz a cópia? Copia o quê? Nesta aula você vai ver as duas funções que o C++ usa para copiar objetos, descobrir quando elas rodam (às vezes em lugares inesperados), conhecer o bug clássico da "cópia rasa" que derruba o programa e aprender as regras que os programadores C++ seguem para nunca cair nele.

Você vai aprender
  • O construtor de cópia Classe(const Classe&) e a atribuição de cópia operator=.
  • Em que linhas cada um é chamado: Classe b = a;, b = a;, passagem por valor, push_back.
  • A diferença entre cópia rasa e cópia profunda, e o erro double free que a cópia rasa causa.
  • A regra dos três, a regra dos cinco e a melhor de todas, a regra do zero.
  • Como proibir cópias com = delete, e o erro que o compilador mostra.
  • Onde entra o movimento (a aula completa é Semântica de Movimento).

Esta aula usa o que você viu em Construtores, Destrutores e RAII e Referências. Os programas foram compilados com o g++ 15 na máquina da Ana, na pasta ~/cpp, com g++ -std=c++23 -Wall -Wextra arquivo.cpp -o programa.

A ideia: xerox ou caderno compartilhado?

A Ana empresta o caderno de receitas para a Bia. Há dois jeitos:

  • Tirar uma xerox de cada página. A Bia pode rabiscar a cópia dela à vontade: o caderno da Ana continua igual.
  • Dar um bilhete dizendo "o caderno está na minha estante". Agora as duas usam o mesmo caderno: o que a Bia rabiscar, a Ana vai ver. E se as duas resolverem jogar "o seu" caderno fora, alguém vai tentar jogar fora um caderno que não existe mais.

Em C++, a xerox é a cópia profunda; o bilhete é a cópia rasa. Para tipos como int, std::string e std::vector, o C++ já faz a xerox sozinho. O perigo aparece quando a classe guarda um ponteiro cru (int*), que é exatamente um "bilhete" dizendo onde está a coisa.

1. As duas funções de cópia

Toda classe tem duas funções responsáveis por copiar. Se você não escrever, o compilador cria as duas, e elas copiam atributo por atributo.

FunçãoFormaQuando roda
Construtor de cópiaClasse(const Classe& outro)Quando um objeto novo nasce como cópia de outro.
Atribuição de cópiaClasse& operator=(const Classe& outro)Quando um objeto que já existe recebe o valor de outro.

Para ver quando cada uma roda, vamos escrevê-las nós mesmos, com um std::cout dentro:

#include <iostream>
#include <string>

class Caderno {
public:
    Caderno(std::string dono) : dono_{dono} {
        std::cout << "  [construtor] " << dono_ << '\n';
    }
    Caderno(const Caderno& outro) : dono_{outro.dono_} {
        std::cout << "  [cópia] copiei o caderno de " << dono_ << '\n';
    }
    Caderno& operator=(const Caderno& outro) {
        std::cout << "  [atribuição] " << dono_ << " recebe o de " << outro.dono_ << '\n';
        dono_ = outro.dono_;
        return *this;
    }
    ~Caderno() {
        std::cout << "  [destrutor] " << dono_ << '\n';
    }
    std::string dono() const { return dono_; }
private:
    std::string dono_;
};

void por_valor(Caderno c) {
    std::cout << "  dentro de por_valor: " << c.dono() << '\n';
}

void por_referencia(const Caderno& c) {
    std::cout << "  dentro de por_referencia: " << c.dono() << '\n';
}

int main() {
    std::cout << "1) criar a\n";
    Caderno a{"Ana"};
    std::cout << "2) Caderno b = a;\n";
    Caderno b = a;
    std::cout << "3) Caderno c{a};\n";
    Caderno c{a};
    std::cout << "4) Caderno d{\"Bia\"}; d = a;\n";
    Caderno d{"Bia"};
    d = a;
    std::cout << "5) por_valor(a)\n";
    por_valor(a);
    std::cout << "6) por_referencia(a)\n";
    por_referencia(a);
    std::cout << "7) fim do main\n";
}
Caderno(const Caderno& outro)
O construtor de cópia. Recebe o objeto original por referência constante: & para não copiar (copiar para poder copiar seria um círculo sem fim) e const porque copiar não deve mudar o original.
: dono_{outro.dono_}
Inicializa o atributo do objeto novo com o do original. Uma classe pode ler os atributos privados de outro objeto da mesma classe.
Caderno& operator=(const Caderno& outro)
A atribuição de cópia: é a função que roda no sinal = entre dois objetos que já existem. O nome operator= é a forma de "ensinar" um operador a uma classe (aula Sobrecarga de Operadores).
return *this;
Devolve o próprio objeto (this), para permitir x = y = z;, como com números.

A pegadinha está no caso 2: Caderno b = a; tem um sinal de igual, mas não chama a atribuição. Como b está nascendo nessa linha, quem roda é o construtor de cópia. A regra para não errar:

Nasce ou já existia?
  • O objeto da esquerda está nascendo nesta linha (tem o tipo na frente)? Construtor de cópia.
  • O objeto da esquerda já existia? Atribuição de cópia (operator=).

Os casos 5 e 6 mostram por que, nas aulas de funções, o guia recomenda const Classe& para objetos (Por Valor × Por Referência): passar por valor fez uma cópia inteira (e uma destruição) só para ler o nome.

Mais dois lugares: return e push_back

Caderno criar() {
    Caderno novo{"Caio"};
    return novo;
}

int main() {
    std::cout << "1) Caderno x = criar();\n";
    Caderno x = criar();
    std::cout << "2) vector + push_back(x)\n";
    std::vector<Caderno> pilha;
    pilha.push_back(x);
    std::cout << "3) fim do main\n";
}

$ g++ -std=c++23 -Wall -Wextra retorno.cpp -o retorno
$ ./retorno

  [construtor] Caio                   « nenhuma cópia no return!
2) vector + push_back(x)

3) fim do main

Devolver um objeto de uma função não copiou nada: o compilador construiu o novo direto no lugar de x. Isso se chama elisão de cópia (copy elision, "omitir a cópia"), e é por isso que devolver objetos por valor é barato em C++. Já o push_back guardou uma cópia de x: o vetor tem o seu próprio caderno.

2. Cópia rasa × cópia profunda

A cópia que o compilador gera copia atributo por atributo. Para um std::string, "copiar o atributo" chama a cópia da própria string, que faz uma xerox do texto. Tudo certo. Mas, para um ponteiro cru, "copiar o atributo" copia só o endereço: o bilhete, não o caderno. Veja uma classe que guarda notas num array criado com new[]:

#include <iostream>

class Notas {
public:
    Notas(int tamanho) : tamanho_{tamanho}, dados_{new int[tamanho]{}} {}
    ~Notas() { delete[] dados_; }

    int tamanho() const { return tamanho_; }
    void definir(int i, int valor) { dados_[i] = valor; }
    int pegar(int i) const { return dados_[i]; }
private:
    int tamanho_;
    int* dados_;
};

int main() {
    Notas ana{3};
    ana.definir(0, 7);

    Notas bia = ana;          // cópia feita pelo compilador
    bia.definir(0, 10);       // mudei só a Bia...

    std::cout << "Ana: " << ana.pegar(0) << '\n';
    std::cout << "Bia: " << bia.pegar(0) << '\n';
}

$ g++ -std=c++23 -Wall -Wextra rasa.cpp -o rasa
$ ./rasa
Ana: 10                  « a nota da Ana mudou sozinha!
Bia: 10
free(): double free detected in tcache 2
Abortado                   (imagem do núcleo gravada) ./rasa
$ echo $?
134

Dois problemas, nenhum aviso do compilador:

  1. Estado compartilhado. bia.dados_ recebeu o mesmo endereço de ana.dados_. As duas apontam para o mesmo array; mudar a Bia mudou a Ana.
  2. Double free ("liberação dupla"). No fim do main, bia morre e faz delete[] no array. Depois ana morre e faz delete[] no mesmo array, que já tinha sido devolvido. A biblioteca C percebeu (double free detected) e abortou o programa.

O conserto à moda antiga: cópia profunda

Para a cópia virar uma xerox, você escreve as duas funções de cópia à mão. Cada uma cria um array novo e copia os valores, um por um:

class Notas {
public:
    Notas(int tamanho) : tamanho_{tamanho}, dados_{new int[tamanho]{}} {}
    ~Notas() { delete[] dados_; }

    // construtor de cópia: memória NOVA, com os mesmos valores
    Notas(const Notas& outra)
        : tamanho_{outra.tamanho_}, dados_{new int[outra.tamanho_]} {
        for (int i = 0; i < tamanho_; ++i) {
            dados_[i] = outra.dados_[i];
        }
    }

    // atribuição de cópia: joga fora o antigo e copia o novo
    Notas& operator=(const Notas& outra) {
        if (this == &outra) return *this;      // a = a; não faz nada
        int* novos = new int[outra.tamanho_];
        for (int i = 0; i < outra.tamanho_; ++i) {
            novos[i] = outra.dados_[i];
        }
        delete[] dados_;
        dados_ = novos;
        tamanho_ = outra.tamanho_;
        return *this;
    }
    // ... tamanho, definir e pegar como antes
private:
    int tamanho_;
    int* dados_;
};
TrechoPor quê
dados_{new int[outra.tamanho_]}O objeto novo ganha o seu próprio array.
o forCopia os valores, um por um: a xerox.
if (this == &outra)Protege contra ana = ana;. Sem isso, o objeto apagaria os próprios dados antes de copiá-los.
new antes do delete[]Se o new falhar (falta de memória), o objeto continua com os dados antigos, inteiro.

3. Regra dos três, dos cinco e do zero

Regra dos três

Se a sua classe precisou de um destes três, quase certamente precisa dos três:

  1. destrutor (~Classe());
  2. construtor de cópia (Classe(const Classe&));
  3. atribuição de cópia (operator=(const Classe&)).

O motivo: se você escreveu um destrutor, é porque a classe cuida de um recurso "na mão" (o delete[]), e a cópia automática não sabe duplicar esse recurso. Foi exatamente o caso da Notas.

Regra dos cinco C++11

O C++11 acrescentou duas funções de movimento: o construtor de movimento Classe(Classe&&) e a atribuição de movimento operator=(Classe&&). Elas "roubam" o recurso de um objeto que vai morrer, em vez de copiá-lo, o que é muito mais rápido. A regra dos três virou a regra dos cinco: quem escreve uma das cinco deve pensar nas cinco. O movimento tem aula própria: Semântica de Movimento.

Regra do zero: a melhor

A recomendação moderna é não escrever nenhuma das cinco. Em vez de guardar um ponteiro cru e cuidar dele à mão, guarde um tipo que já sabe se copiar, mover e destruir (RAII, da aula anterior): std::vector, std::string, std::unique_ptr. A cópia automática, atributo por atributo, passa a fazer a coisa certa:

#include <iostream>
#include <vector>

class Notas {
public:
    Notas(int tamanho) : dados_(tamanho) {}

    int tamanho() const { return static_cast<int>(dados_.size()); }
    void definir(int i, int valor) { dados_[i] = valor; }
    int pegar(int i) const { return dados_[i]; }
private:
    std::vector<int> dados_;
};

int main() {
    Notas ana{3};
    ana.definir(0, 7);

    Notas bia = ana;
    bia.definir(0, 10);

    std::cout << "Ana: " << ana.pegar(0) << '\n';
    std::cout << "Bia: " << bia.pegar(0) << '\n';
}

$ g++ -std=c++23 -Wall -Wextra zero.cpp -o zero
$ ./zero
Ana: 7
Bia: 10

Sem destrutor, sem construtor de cópia, sem operator=, sem new: a classe ficou menor e correta. Repare no dados_(tamanho) com parênteses: para std::vector, (3) cria três elementos valendo zero, enquanto {3} criaria um elemento só, valendo 3 (detalhe da aula std::vector).

RegraQuando usar
ZeroQuase sempre. Atributos que já se cuidam (string, vector, unique_ptr…) e nenhuma das cinco funções escrita à mão.
CincoQuando você escreve uma classe que é o dono de um recurso cru (como a Arquivo da aula anterior). Escreva as cinco, ou proíba as que não fazem sentido.
TrêsO mesmo que a dos cinco, em código anterior ao C++11.

4. Proibir a cópia com = delete

Alguns objetos não deveriam ser copiados de jeito nenhum: um arquivo aberto, uma conexão com o banco, uma senha guardada na memória. Para proibir, declare as funções de cópia e escreva = delete no lugar do corpo C++11:

#include <iostream>
#include <string>

class Senha {
public:
    Senha(std::string texto) : texto_{texto} {}

    Senha(const Senha&) = delete;             // proíbe: Senha b = a;
    Senha& operator=(const Senha&) = delete;  // proíbe: b = a;

    bool confere(const std::string& tentativa) const { return tentativa == texto_; }
private:
    std::string texto_;
};

int main() {
    Senha minha{"gato123"};
    Senha copia = minha;
    std::cout << copia.confere("gato123") << '\n';
}

= default: o contrário

Se você quer deixar claro que a cópia automática está boa, escreva Classe(const Classe&) = default;: "use a versão que o compilador gera". Pela regra do zero, normalmente nem isso é preciso.

Quando dá errado

"free(): double free detected in tcache 2" 
$ ./rasa
Ana: 10
Bia: 10
free(): double free detected in tcache 2
Abortado                   (imagem do núcleo gravada) ./rasa

O que significa: a mesma memória foi liberada duas vezes. Quase sempre é uma classe com ponteiro cru e destrutor, mas com a cópia automática (rasa). tcache é um detalhe interno da biblioteca C; não ajuda a achar o erro. O código de saída é 134 (abortado).

Como consertar: regra do zero (troque o ponteiro cru por std::vector, std::string ou std::unique_ptr), ou escreva a cópia profunda, ou proíba a cópia com = delete. Para achar onde, compile com -g -fsanitize=address.

Mudei uma cópia e o original mudou junto

O que significa: é a outra cara da cópia rasa: os dois objetos dividem o mesmo recurso por um ponteiro. Pode acontecer sem nenhum erro visível, se a classe não tiver destrutor (e aí ela vaza memória).

Como consertar: o mesmo do cenário anterior.

"use of deleted function" ao passar para uma função

O que significa: a classe proíbe cópias (como Senha, std::unique_ptr ou std::ofstream), e a função recebe o parâmetro por valor, o que exigiria uma cópia.

Como consertar: receba por referência (const Senha&). Se a intenção é entregar o objeto para a função, use std::move (aula Semântica de Movimento).

O operator= apagou os próprios dados

O que significa: um operator= escrito à mão que faz delete[] dados_ antes de copiar quebra em a = a;: ele apaga o array e depois tenta copiar do array apagado. Isso também acontece de forma escondida, como em lista[i] = lista[j]; quando i == j.

Como consertar: teste if (this == &outra) return *this; e crie o array novo antes de apagar o antigo. Ou, melhor, regra do zero.

Missão 2 (provoque o erro): uma Chave do cofre não pode ter cópias. Acrescente na classe as duas linhas com = delete que proíbem copiar e rode: a compilação deve falhar na linha Chave reserva = chave;, com um erro que fala de função deleted.

#include <iostream>
#include <string>

class Chave {
public:

Resumo

  • O construtor de cópia Classe(const Classe&) roda quando um objeto nasce como cópia (inclusive em Classe b = a;, passagem por valor e push_back).
  • A atribuição de cópia operator= roda quando um objeto que já existe recebe outro.
  • A cópia automática copia atributo por atributo. Com ponteiro cru, isso é uma cópia rasa: estado compartilhado e double free.
  • Cópia profunda = memória nova + copiar os valores. Funciona, mas dá trabalho.
  • Regra dos três/cinco: escreveu uma das funções especiais, pense em todas. Regra do zero: prefira atributos RAII e não escreva nenhuma.
  • = delete proíbe a cópia com erro de compilação (use of deleted function).
  • Devolver objeto por valor costuma não copiar nada (elisão de cópia). O movimento, a outra metade desta história, está em Semântica de Movimento.
