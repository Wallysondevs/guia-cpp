C++ Mensagens de Erro

O compilador de C++ é exigente e fala inglês. Quando algo dá errado, ele escreve o arquivo, a linha, a coluna e uma frase curta, às vezes seguida de dezenas de linhas de "notas". Esta página junta as mensagens que você mais vai encontrar: de compilação, de ligação e de execução. Cada uma vem com o código que a provoca, o que ela quer dizer, como consertar e a aula onde o assunto é explicado. Todas foram provocadas de verdade no g++ 15.2 e no clang++ 21 da máquina da Ana.

Como usar esta página
  • Copie um pedaço da mensagem que apareceu para você (por exemplo, was not declared) e procure aqui com Ctrl+F.
  • Os programas ficam na pasta ~/erros da Ana. No seu computador, o nome do arquivo e o número da linha serão outros; o texto da mensagem é o mesmo.
  • As mensagens do g++ saem em inglês, com aspas tipográficas ‘assim’. As do ligador (ld) e do terminal saem em português na máquina da Ana, porque esses programas têm tradução instalada; a versão em inglês aparece logo ao lado.
  • O editor do guia usa o Clang, não o g++. Por isso, os 10 erros mais comuns têm as duas versões lado a lado. Veja também O Editor do Guia.
  • Todos os programas foram compilados com o comando padrão do guia: g++ -std=c++23 -Wall -Wextra arquivo.cpp -o programa (veja Compilar com g++).

Regra de ouro: conserte o primeiro erro e compile de novo

Repare no terceiro erro: ‘quantidade’ was not declared. Mas a variável está declarada na linha 5! Por causa do ; que faltou, o compilador entendeu as linhas 4 e 5 como uma coisa só e "perdeu" a declaração. Um erro costuma provocar outros, em cascata. Por isso: leia o primeiro, conserte, compile de novo. A aula Lendo Erros do Compilador treina isso com calma.

6. invalid conversion from ‘const char*’ to ‘int’ — tipo errado 
$ cat tipo.cpp
int main() {
    int idade = "30";
    return idade;
}
$ g++ -std=c++23 -Wall -Wextra tipo.cpp -o tipo
tipo.cpp: In function ‘int main()’:
tipo.cpp:2:17: error: invalid conversion from ‘const char*’ to ‘int’ [-fpermissive]
    2 |     int idade = "30";
      |                 ^~~~
      |                 |
      |                 const char*
$ clang++ -std=c++23 -Wall -Wextra tipo.cpp -o tipo
tipo.cpp:2:9: error: cannot initialize a variable of type 'int' with an lvalue of type 'const char[3]'
    2 |     int idade = "30";
      |         ^       ~~~~
1 error generated.

O que significa: "30", entre aspas, é texto (para o compilador, const char* ou const char[3]: dois caracteres mais o final invisível), e a variável é int. O C++ não converte texto em número sozinho.

Parentes: char letra = "A"; dá invalid conversion from ‘const char*’ to ‘char’ (use aspas simples: 'A'); std::string s = 5; dá conversion from ‘int’ to non-scalar type ‘std::string’ … requested (clang++: no viable conversion from 'int' to 'std::string').

Como consertar: tire as aspas (int idade = 30;) ou, se o texto vem de fora, converta com std::stoi. Aulas: Tipos de Dados, Texto ↔ Número, char.

10. expected ‘}’ at end of input — faltou fechar uma chave 
$ cat chave.cpp
#include <iostream>

int main() {
    if (true) {
        std::cout << "oi\n";
}
$ g++ -std=c++23 -Wall -Wextra chave.cpp -o chave
chave.cpp: In function ‘int main()’:
chave.cpp:6:2: error: expected ‘}’ at end of input
    6 | }
      |  ^
chave.cpp:3:12: note: to match this ‘{’
    3 | int main() {
      |            ^
$ clang++ -std=c++23 -Wall -Wextra chave.cpp -o chave
chave.cpp:6:2: error: expected '}'
    6 | }
      |  ^
chave.cpp:3:12: note: to match this '{'
    3 | int main() {
      |            ^

O que significa: o arquivo acabou ("end of input") com uma { ainda aberta. A nota aponta a chave que ficou sem par, mas atenção: o compilador casa cada } com a { aberta mais recente, então a chave que de fato ficou sem fechar (aqui, a do if) pode ser outra.

O contrário, uma } sobrando, dá expected declaration before ‘}’ token (clang++: extraneous closing brace ('}')).

Como consertar: mantenha a indentação certinha (o editor ajuda) e confira bloco por bloco. Aula: Sintaxe.

Quando o erro acontece dentro de um template da biblioteca (std::sort, std::vector, cout <<…), o compilador mostra o caminho inteiro por dentro dela. O cout << v do erro 7 rende 378 linhas no g++. Não se assuste; procure três coisas:

  1. a primeira linha com error:;
  2. a linha required from here que aponta um arquivo seu (é a sua linha que causou tudo);

Erros de ligação (ld)

Depois de compilar cada .cpp, o g++ chama o ligador (ld, de linker), que junta as peças num programa só. Os erros dele não têm número de linha: em vez de arquivo.cpp:5:5:, aparecem nomes de arquivos temporários (/tmp/ccsEstGP.o) e a frase collect2: error: ld returned 1 exit status ("o ld terminou com erro"). Causas e consertos:

  • esqueceu um .cpp no comando: g++ … main.cpp soma.cpp -o main;
  • o nome ou os parâmetros da definição não batem com a declaração (int Soma(int a, int b) no .cpp, int soma(int, int) no .h: maiúscula conta);

Causas típicas: usar um ponteiro nulo (*p com p = nullptr), um ponteiro para algo que já foi apagado, um índice muito fora do array, ou uma recursão sem fim, que estoura a pilha (a conta(n + 1) sem caso de parada deu a mesma mensagem e o mesmo 139).

Relatórios dos sanitizers (resumidos)

Os sanitizers são "fiscais" que o compilador põe dentro do programa para pegar erros de memória e comportamento indefinido na linha exata, mesmo quando o programa parece funcionar. Compile com -g -fsanitize=address,undefined. Aula completa: Sanitizers.

Um exemplo inteiro: o laço vai até i <= 3 num array de 3 itens criado com new.

#include <iostream>

int main() {
    int* notas = new int[3]{7, 9, 8};
    int soma = 0;
    for (int i = 0; i <= 3; i++) {
        soma += notas[i];
    }
    std::cout << soma << '\n';
    delete[] notas;
}

E no editor do guia?

O editor compila com o Clang e roda o programa como WebAssembly, dentro do navegador. Os erros de compilação são os da coluna do clang++. Resumo

  • Leia arquivo:linha:coluna: error: texto, conserte o primeiro erro e compile de novo: os outros costumam ser cascata.
  • error impede o programa; warning deixa criar, mas aponta defeito; note explica a mensagem anterior. Compile com -Wall -Wextra e zere os avisos.
  • O editor do guia usa o Clang: as palavras mudam (was not declared × use of undeclared identifier), o sentido é o mesmo.
  • Erro de ligação (undefined reference, multiple definition, ld returned 1 exit status): falta ou sobra uma peça entre os arquivos.
  • Erros de execução: 139 = Segmentation fault, 136 = Floating point exception, 134 = Aborted (exceção não capturada, double free, asserção).
  • Para achar a linha de um erro de memória, use -g -fsanitize=address,undefined e leia o SUMMARY.
