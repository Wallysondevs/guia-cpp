C++ std::unordered_map

O std::map guarda pares chave → valor sempre em ordem alfabética. Manter essa ordem tem um custo: a cada busca, ele compara a chave com várias outras. O std::unordered_map ("map não ordenado") abre mão da ordem e, em troca, acha a chave quase de uma vez só, com uma conta. Por fora, os dois se usam do mesmo jeito: [], at, find, contains, erase. Por dentro, é outra máquina: uma tabela de espalhamento.

Você vai aprender
  • O que é uma tabela de espalhamento (hash table) e o que é um hash.
  • Por que a ordem do unordered_map sai "bagunçada", com a saída real, e por que ela pode mudar.
  • Por que ele é mais rápido em média, com uma medição pequena.
  • Que a interface é a mesma do map: trocar um pelo outro costuma ser só trocar o nome.
  • O erro de quando a chave não sabe "se espalhar" (uma struct como chave).
  • Uma tabela map × unordered_map para escolher.

Todos os programas desta aula foram compilados com o g++ 15.2 na máquina fictícia da Ana, na pasta ~/cpp/umap, com g++ -std=c++23 -Wall -Wextra arquivo.cpp -o programa. Leia antes a aula std::map: esta aula se apoia nela.

A ideia: o vestiário com armários numerados

No clube, o vestiário tem 13 armários numerados de 0 a 12. A regra para escolher o armário é uma conta com o nome da pessoa: some o "valor" das letras do nome e pegue o resto da divisão por 13. A Ana sempre cai no armário 5, o Bruno sempre no 10. Para achar as coisas da Ana, ninguém procura armário por armário: faz a conta com "Ana", dá 5, abre o 5.

Repare em três coisas:

  • Achar é rápido: uma conta e um armário, não importa se há 10 ou 10 mil sócios.
  • Não há ordem alfabética: olhando os armários do 0 ao 12, os nomes aparecem na ordem que a conta decidiu.
  • Dois nomes podem cair no mesmo armário (uma "colisão"). Tudo bem: o armário guarda os dois, e você confere qual é qual. Se começar a encher demais, o clube constrói um vestiário maior e redistribui todo mundo, e aí cada um pode cair num número diferente.
No vestiárioNo unordered_map
A conta com o nomeA função de hash ("espalhamento", "picadinho"): transforma a chave num número grande
Os armáriosOs buckets ("baldes", "gavetas")
O resto da divisão pelo número de armáriosQual gaveta: hash % número_de_gavetas
Dois nomes no mesmo armárioUma colisão
Construir um vestiário maior e redistribuirRehash: mais gavetas, e todo mundo muda de lugar

1. A ordem "bagunçada"

A Ana pôs o mesmo estoque num map e num unordered_map e mostrou as chaves dos dois:

#include <iostream>
#include <map>
#include <string>
#include <unordered_map>

int main() {
    std::map<std::string, int> m{
        {"maçã", 12}, {"banana", 30}, {"pera", 8}, {"uva", 40}, {"kiwi", 5}};
    std::unordered_map<std::string, int> u{
        {"maçã", 12}, {"banana", 30}, {"pera", 8}, {"uva", 40}, {"kiwi", 5}};

    std::cout << "map:           ";
    for (const auto& [nome, qtd] : m) {
        std::cout << nome << ' ';
    }
    std::cout << "\nunordered_map: ";
    for (const auto& [nome, qtd] : u) {
        std::cout << nome << ' ';
    }
    std::cout << '\n';
}
#include <unordered_map>

O map saiu em ordem alfabética. O unordered_map saiu em uma ordem que não é alfabética, nem a de inserção, nem a contrária: é a ordem das gavetas. Dá para espiar as contas:

#include <functional>
#include <iostream>
#include <string>
#include <unordered_map>

int main() {
    std::unordered_map<std::string, int> estoque{
        {"maçã", 12}, {"banana", 30}, {"pera", 8}};

    std::cout << "gavetas: " << estoque.bucket_count() << '\n';

    std::hash<std::string> espalhar;
    for (const auto& [nome, qtd] : estoque) {
        std::cout << nome << ": hash = " << espalhar(nome)
                  << ", gaveta " << estoque.bucket(nome) << '\n';
    }
}

Nunca dependa da ordem de um unordered_map

A ordem muda quando você insere itens, pode mudar com outra versão do compilador e muda de biblioteca para biblioteca: no editor do guia, que usa outra biblioteca padrão (a libc++), o mesmo ordem.cpp mostra kiwi uva banana pera maçã. Se a saída do seu programa precisa estar em ordem, use std::map, ou copie os itens para um vector e ordene (aula Algoritmos).

2. A mesma interface do map

Tudo o que você aprendeu na aula std::map vale aqui: [] (que cria a chave), at (que lança std::out_of_range), contains, find, count, erase, insert, emplace, size. O contador de palavras da aula anterior, trocando só o tipo:

#include <iostream>
#include <string>
#include <unordered_map>

int main() {
    std::unordered_map<std::string, int> contagem;
    std::string palavra;

    while (std::cin >> palavra) {
        ++contagem[palavra];
    }

    std::cout << "Quantos \"o\"? " << contagem.at("o") << '\n';
    std::cout << std::boolalpha << "Tem \"cão\"? " << contagem.contains("cão") << '\n';

    for (const auto& [p, vezes] : contagem) {
        std::cout << p << ": " << vezes << '\n';
    }
}

O que o unordered_map tem a mais são os métodos das gavetas (bucket_count, bucket, load_factor, reserve). O que ele tem a menos: as buscas por faixa que dependem de ordem, como lower_bound ("a primeira chave a partir de "m""), que só o map tem.

3. Mais rápido em média

Para achar uma chave, o map desce por uma árvore ordenada: compara com a chave do meio, vai para a esquerda ou para a direita, compara de novo… Com 100 mil chaves, são umas 17 comparações de texto por busca. O unordered_map faz uma conta de hash, vai na gaveta e compara com o que estiver lá (normalmente um ou dois itens). A Ana mediu 100 mil buscas em cada um:

#include <chrono>
#include <iostream>
#include <map>
#include <string>
#include <unordered_map>
#include <vector>

int main() {
    const int N = 100000;
    std::vector<std::string> nomes;
    for (int i = 0; i < N; ++i) {
        nomes.push_back("produto" + std::to_string(i));
    }

    std::map<std::string, int> m;
    std::unordered_map<std::string, int> u;
    for (const auto& n : nomes) {
        m[n] = 1;
        u[n] = 1;
    }

    using relogio = std::chrono::steady_clock;
    using ms = std::chrono::duration<double, std::milli>;
    long long achados = 0;

    auto t0 = relogio::now();
    for (const auto& n : nomes) achados += m.count(n);
    auto t1 = relogio::now();
    for (const auto& n : nomes) achados += u.count(n);
    auto t2 = relogio::now();

    std::cout << "100 mil buscas no map:           " << ms(t1 - t0).count() << " ms\n";
    std::cout << "100 mil buscas no unordered_map: " << ms(t2 - t1).count() << " ms\n";
    std::cout << "achados: " << achados << '\n';
}

$ g++ -std=c++23 -Wall -Wextra rapidez.cpp -o rapidez
$ ./rapidez
100 mil buscas no map:           176.942 ms
100 mil buscas no unordered_map: 36.7346 ms
achados: 200000

Umas 5 vezes mais rápido, nessa máquina, sem otimização (-O2 deixaria os dois mais rápidos). Os tempos mudam a cada execução; o que vale é a proporção. Em termos de custo (aula list e deque): o map busca em tempo logarítmico, O(log n), que cresce bem devagar; o unordered_map busca em tempo constante em média, O(1).

"Em média"

Se muitas chaves caírem na mesma gaveta (por azar ou de propósito, com chaves escolhidas por um atacante), as buscas nessa gaveta viram uma procura item por item. É raro com chaves comuns, mas é por isso que se diz "rápido em média", e não "sempre". O map é um pouco mais lento, mas tem o mesmo desempenho sempre.

4. A chave precisa saber "se espalhar"

O map exige que a chave saiba fazer < (para ordenar). O unordered_map exige outra coisa: que exista um std::hash para o tipo da chave (para calcular a gaveta), e que ela saiba fazer == (para conferir dentro da gaveta). Textos, números, char e bool já vêm com hash. Uma struct sua, não:

#include <string>
#include <unordered_map>

struct Produto {
    std::string nome;
    int lote;
};

int main() {
    std::unordered_map<Produto, int> estoque;
    estoque[Produto{"maçã", 1}] = 12;
}

Esse erro tem 84 linhas. Aqui estão as 13 primeiras, que são as que importam:

5. map × unordered_map: qual usar

std::mapstd::unordered_map
Cabeçalho<map><unordered_map>

MemóriaUm nó por itemUm nó por item, mais o vetor de gavetas

Regra prática: se você precisa dos itens em ordem (um relatório, uma lista alfabética), ou de buscas por faixa, use map. Se só vai guardar e procurar por chave, e há muitos itens, use unordered_map. Com poucas dezenas de itens, a diferença de velocidade não aparece; escolha pela ordem.

Quando dá errado

"A saída mudou de ordem" / "no meu computador saiu diferente"

O que significa: o programa mostra os itens de um unordered_map e conta com uma ordem que não existe.

Como consertar: use std::map, ou copie as chaves para um std::vector e ordene antes de mostrar.

static assertion failed: hash function must be copy constructible (e dezenas de use of deleted function)

O que significa: o tipo da chave não tem std::hash.

Como consertar: mude a chave para um tipo com hash (std::string, int…) ou use std::map.

error: ‘unordered_map’ is not a member of ‘std’

O que significa: faltou o #include <unordered_map>. O <map> não o traz.

Como consertar: inclua <unordered_map>.

Chaves aparecendo com valor 0 sem ninguém ter cadastrado

O que significa: o mesmo problema do map: ler com [] cria a chave.

Como consertar: para ler, contains, find ou at.

Resumo

  • std::unordered_map é uma tabela de espalhamento: um hash da chave decide a gaveta (bucket) onde o par fica.
  • Sem ordem: os itens saem na ordem das gavetas, que muda com inserções (rehash) e de uma biblioteca para outra.
  • Mais rápido em média (O(1)) que o map (O(log n)) para buscar, inserir e apagar.
  • Mesma interface do map: [] (cria a chave!), at, contains, find, erase…
  • A chave precisa de std::hash e ==; textos e números já têm.
  • Precisa de ordem: map. Só guardar e achar: unordered_map.
  • Próximo passo: guardar só chaves, sem valores, em std::set.
