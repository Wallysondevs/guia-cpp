C++ Algoritmos

A biblioteca padrão do C++ traz dezenas de algoritmos prontos: funções que ordenam, procuram, contam, somam, copiam e apagam itens de uma coleção. Esta página é uma consulta rápida: cada linha tem a forma de chamar (simplificada), o que a função faz, um exemplo e o resultado real, conferido com o g++ 15 na máquina da Ana. Para aprender com calma, veja as aulas Algoritmos, Iteradores, Lambdas e Ranges.

Como ler as tabelas
  • Quase todos os exemplos usam este vetor (cada exemplo começa do zero, com os valores originais): 
    std::vector<int> v{5, 3, 8, 1, 3};
  • Resultado mostra um valor (20, true) ou como o vetor ficou, no formato em que o std::println("{}", v) do C++23 escreve um vetor: [1, 3, 3, 5, 8]. Veja std::format e std::print.
  • Os algoritmos clássicos recebem um começo e um fim: v.begin() aponta o primeiro item e v.end() aponta um depois do último. Na assinatura, eles aparecem como (início, fim).
  • Muitos devolvem um iterador (um "marcador de posição"), e não o valor. Para ver o valor, use *it; para saber a posição, it - v.begin(). "Posição 2" quer dizer o terceiro item (a contagem começa em 0). Se nada foi achado, o iterador é igual a v.end(). Veja Iteradores.
  • pred é um predicado: uma função que recebe um item e responde true ou false, quase sempre uma lambda como [](int x) { return x > 5; }. comp é uma comparação: recebe dois itens e responde "o primeiro vem antes?".
  • Todos os exemplos foram compilados com g++ -std=c++23 -Wall -Wextra (g++ 15.2) e também com o clang++ 21.

A ideia: uma caixa de ferramentas

Imagine que a Ana tem uma pilha de provas para corrigir. Ela pode inventar, toda vez, um jeito de pôr as provas em ordem, achar a maior nota ou contar quantos passaram. Ou pode abrir a caixa de ferramentas da escola, onde já existe uma ferramenta pronta para cada tarefa, testada por milhares de pessoas.

Os algoritmos são essa caixa. Em vez de escrever um laço for para achar o maior número, você chama std::max_element. O código fica menor, diz o que faz (e não só como) e tem menos chance de erro.

Um programa completo, com quatro algoritmos:

#include <algorithm>   // sort, count, max_element...
#include <iostream>
#include <numeric>     // accumulate
#include <vector>

int main() {
    std::vector<int> v{5, 3, 8, 1, 3};

    std::sort(v.begin(), v.end());
    for (int x : v) {
        std::cout << x << ' ';
    }
    std::cout << '\n';

    std::cout << "quantos 3: " << std::count(v.begin(), v.end(), 3) << '\n';
    std::cout << "soma: " << std::accumulate(v.begin(), v.end(), 0) << '\n';
    std::cout << "maior: " << *std::max_element(v.begin(), v.end()) << '\n';
}

Traz os algoritmos "de conta": accumulate, reduce, iota.
std::sort(v.begin(), v.end())
Ordena do começo ao fim, do menor para o maior. Muda o próprio vetor.
std::count(v.begin(), v.end(), 3)
Conta quantos itens são iguais a 3. Não muda nada.
std::accumulate(…, 0)
Soma tudo, começando do valor inicial 0.
*std::max_element(…)
max_element devolve um iterador que aponta o maior; o * pega o valor que está lá.

Remover itens

Aqui mora a maior surpresa da biblioteca: std::remove e std::unique não apagam nada. Eles só empurram os itens que ficam para a frente e devolvem um iterador para o "novo fim"; o tamanho do vetor continua o mesmo, e o que sobra depois do novo fim é lixo. Quem apaga de verdade é o método erase do vetor. Desde o C++20, std::erase e std::erase_if fazem tudo numa linha só.

A família std::ranges C++20

Desde o C++20, quase todo algoritmo tem uma versão em std::ranges:: que recebe o container inteiro, sem begin()/end(). Ela também aceita uma projeção: o campo pelo qual comparar. E dá mensagens de erro mais diretas quando o container não serve. Veja a aula Ranges.

Views: filtrar e transformar sem copiar C++20

Uma view ("visão") é uma janela sobre a coleção: ela mostra os itens de outro jeito (só os pares, multiplicados por 10, de trás para a frente) sem copiar nem mudar o original. Os itens só são calculados quando alguém percorre a view (ela é "preguiçosa"). As views se encadeiam com a barra |, como canos. Ficam em <ranges>.

Encadeando: os itens maiores que 2, multiplicados por 10, depois de ordenar. Repare que, nas views, a ordem da leitura é a ordem em que as coisas acontecem.

#include <algorithm>
#include <iostream>
#include <ranges>
#include <vector>

int main() {
    std::vector<int> v{5, 3, 8, 1, 3};

    std::ranges::sort(v);

    auto grandes = v | std::views::filter([](int x) { return x > 2; })
                     | std::views::transform([](int x) { return x * 10; });

    for (int x : grandes) {
        std::cout << x << ' ';
    }
    std::cout << '\n';
}

Clássico ou ranges: qual usar?
  • Em código novo com C++20 ou mais, prefira std::ranges::: é mais curto, não tem como trocar o begin de um vetor pelo end de outro, e aceita projeção.
  • A forma clássica continua valendo e aparece em todo código antigo, em livros e em respostas na internet; você precisa saber ler as duas. Ela também é a única que funciona num pedaço do vetor sem views (std::sort(v.begin(), v.begin() + 3)).
  • Os algoritmos <numeric> (accumulate, reduce) não têm versão ranges::; o substituto do C++23 é o std::ranges::fold_left.
  • Use views quando quiser só olhar os itens de outro jeito; use o algoritmo quando quiser mudar o container.

Armadilhas (resultados reais)

std::remove "não removeu"

Depois de std::remove(v.begin(), v.end(), 3); sozinho, o vetor ficou [5, 8, 1, 1, 3], ainda com 5 itens. Os dois últimos são sobras. Por sorte, o g++ 15 avisa quando você joga fora o "novo fim" que o remove (e o unique) devolve:

$ g++ -std=c++23 -Wall -Wextra rem.cpp -o rem
rem.cpp: In function ‘int main()’:
rem.cpp:7:16: warning: ignoring return value of ‘constexpr _FIter std::remove(_FIter, _FIter, const _Tp&) [with _FIter = __gnu_cxx::__normal_iterator<int*, vector<int> >; _Tp = int]’, declared with attribute ‘nodiscard’ [-Wunused-result]
    7 |     std::remove(v.begin(), v.end(), 3);
      |     ~~~~~~~~~~~^~~~~~~~~~~~~~~~~~~~~~~
In file included from /usr/include/c++/15/algorithm:63,
                 from rem.cpp:1:
/usr/include/c++/15/bits/stl_algo.h:772:5: note: declared here
  772 |     remove(_ForwardIterator __first, _ForwardIterator __last,
      |     ^~~~~~

O que significa: "ignorando o valor de retorno de std::remove, que foi declarada com o atributo nodiscard" (não descartar). O resultado era importante e você o jogou fora. O Clang diz o mesmo: warning: ignoring return value of function declared with 'nodiscard' attribute.

Como consertar: use std::erase(v, 3); (C++20) ou a dupla v.erase(std::remove(v.begin(), v.end(), 3), v.end());.

std::unique deixou repetidos

No vetor original [5, 3, 8, 1, 3], unique + erase não muda nada: os dois 3 não estão lado a lado.

Como consertar: ordene antes (std::sort), aí os repetidos ficam vizinhos e o resultado é [1, 3, 5, 8]. Se precisar de itens únicos sempre, considere um std::set.

binary_search num vetor fora de ordem

Em [5, 3, 8, 1, 3], sem ordenar, std::binary_search(v.begin(), v.end(), 8) deu true, mas std::binary_search(v.begin(), v.end(), 5) deu false, embora o 5 esteja lá, na primeira posição.

O que significa: a busca binária supõe que o vetor está ordenado; se não estiver, a resposta é qualquer coisa. Nenhum erro, nenhum aviso.

Como consertar: ordene antes, ou use std::find/std::ranges::contains, que funcionam em qualquer ordem.

A média saiu errada com accumulate

Com std::vector<double> notas{9.5, 7.0, 8.5};, std::accumulate(notas.begin(), notas.end(), 0) deu 24, e não 25.

O que significa: o valor inicial 0 é um int, então a conta inteira é feita em int: a cada passo, a parte decimal é jogada fora (0 + 9.5 → 9; 9 + 7 → 16; 16 + 8.5 → 24). Nem o -Wall -Wextra avisa, porque a conversão acontece dentro do cabeçalho da biblioteca.

Como consertar: comece com 0.0: std::accumulate(notas.begin(), notas.end(), 0.0) dá 25. Veja Conversão de Tipos.

*max_element (ou *find) sem conferir

Num vetor vazio, std::max_element(v.begin(), v.end()) devolve v.end(); num find que não acha, também. Usar * nesse iterador lê memória que não é do vetor: é comportamento indefinido, e o programa pode mostrar lixo, travar ou parecer funcionar.

Como consertar: confira antes: if (it != v.end()) { … *it … }, ou confira v.empty(). Os sanitizers ajudam a achar esse erro.

std::sort num std::list 
#include <algorithm>
#include <list>

int main() {
    std::list<int> l{5, 3, 8};
    std::sort(l.begin(), l.end());

#include <algorithm>
#include <iostream>
#include <numeric>
#include <vector>

int main() {
    std::vector<int> notas{7, 4, 9, 6, 10, 5};

    // 1. conte as notas maiores ou iguais a 7 com std::count_if
    auto aprovados = std::count_if(notas.begin(), notas.end(),

    // 2. ache a maior nota com std::max_element
    int maior = *std::max_element(notas.begin(), notas.end());

    std::cout << "maior: " << maior << '\n';
    std::cout << "soma: " << soma << '\n';
}

Resumo

  • Os algoritmos ficam em <algorithm> (quase todos) e <numeric> (accumulate, reduce, iota); as views, em <ranges>.
  • Forma clássica: algoritmo(v.begin(), v.end(), …). Forma C++20: std::ranges::algoritmo(v, …).
  • find, min_element, max_element e lower_bound devolvem iteradores: compare com v.end() antes de usar *.
  • remove e unique não apagam: use std::erase/std::erase_if (C++20) ou a dupla erase-remove. unique só junta vizinhos.
  • binary_search, lower_bound e upper_bound só funcionam em coleções ordenadas.
  • No accumulate, o tipo do valor inicial manda: 0.0 para somar double.
  • Views (filter, transform, take…) mostram os itens de outro jeito sem copiar nem mudar o original.
