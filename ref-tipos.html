C++ Tipos e Limites

Quantos bytes tem um int? Qual o maior número que cabe num short? Que tipo tem o literal 42ul? Esta página responde de uma vez, em tabelas. Todos os valores foram medidos na máquina da Ana (Linux x86-64, g++ 15.2) com sizeof e std::numeric_limits. Para aprender com calma, veja Tipos de Dados, Inteiros, float e double, char e bool.

Como ler as tabelas
  • Bytes é o resultado de sizeof(tipo). Um byte tem 8 bits.
  • O padrão do C++ só garante tamanhos mínimos (um int tem pelo menos 16 bits, um long pelo menos 32…). Os tamanhos exatos dependem do sistema: as tabelas valem para o Linux x86-64 (e quase todas para o macOS). As diferenças estão em Outros sistemas.
  • No Windows, long tem 4 bytes, não 8. Se o número pode passar de 2 bilhões, use long long ou std::int64_t.
  • O editor do guia gera WebAssembly de 32 bits: lá, long, ponteiros e size_t têm 4 bytes.

Para conferir no seu computador

#include <cstdint>
#include <iostream>
#include <limits>

int main() {
    std::cout << "int: " << sizeof(int) << " bytes, de "
              << std::numeric_limits<int>::min() << " a "
              << std::numeric_limits<int>::max() << '\n';
    std::cout << "long: " << sizeof(long) << " bytes\n";
    std::cout << "int64_t até " << std::numeric_limits<std::int64_t>::max() << '\n';
    std::cout << "double: " << std::numeric_limits<double>::digits10
              << " dígitos garantidos\n";
}

$ ./tamanhos

Ponto flutuante

Aula: float e double. "Dígitos" é digits10: quantos dígitos decimais sempre sobrevivem à ida e volta.

TipoBytesDígitosMenor positivo normal (min)MáximoEpsilonLiteral
float461.1754944e-383.4028235e+381.1920929e-073.14f
double8152.2250738585072014e-3081.7976931348623157e+3082.220446049250313e-163.14
long double16 (Windows MSVC e macOS ARM: 8)183.3621031431120935063e-49321.189731495357231765e+49321.084202172485504434e-193.14L
  • O mais negativo é lowest(), igual a −max() (por exemplo, −1.7976931348623157e+308). Atenção: min() de ponto flutuante é o menor positivo, não o mais negativo.
  • Epsilon é a distância entre 1 e o próximo número representável: a "resolução" do tipo perto de 1.
  • Use double como padrão. float só quando a memória importa muito (gráficos, milhões de valores).
  • No x86-64 Linux, o long double ocupa 16 bytes, mas usa 80 bits de precisão (o resto é enchimento).

Nenhum deles guarda 0,1 exatamente. Com 20 casas (std::format("{:.20f}", …)): 0.1f → 0.10000000149011611938 e 0.1 → 0.10000000000000000555. E 0.1 + 0.2 == 0.3 é false: a soma dá 0.30000000000000004.

Inteiros de tamanho fixo: <cstdint>

Quando o tamanho exato importa (arquivos binários, rede, ou só para não depender do sistema), use os tipos de <cstdint>. Eles são apelidos para os tipos acima: no Linux x86-64, std::int64_t é long; no Windows, long long. O nome diz o tamanho em todo lugar.

Armadilhas

1. std::uint8_t sai como letra. Ele é um unsigned char, e o cout mostra char como caractere:

#include <cstdint>
#include <iostream>

int main() {
    std::uint8_t idade = 65;
    std::cout << "Idade: " << idade << '\n';
    std::cout << "Idade: " << +idade << '\n';
    std::cout << "Idade: " << static_cast<int>(idade) << '\n';
}

$ g++ -std=c++23 -Wall -Wextra uint8.cpp -o uint8
$ ./uint8
Idade: A
Idade: 65
Idade: 65

65 é o código do A. O + na frente promove para int; o static_cast<int> diz o mesmo de forma explícita. O std::format("{}", idade) mostra 65.

2. Estouro: o valor não cabe.

#include <climits>
#include <iostream>

int main() {
    int a = 3000000000;
    int b = INT_MAX + 1;
    unsigned c = -1;
    short d = 70000;
    std::cout << a << ' ' << b << ' ' << c << ' ' << d << '\n';
}

$ g++ -std=c++23 -Wall -Wextra estouro.cpp -o estouro
estouro.cpp: In function ‘int main()’:
estouro.cpp:6:21: warning: integer overflow in expression of type ‘int’ results in ‘-2147483648’ [-Woverflow]
    6 |     int b = INT_MAX + 1;
      |                     ^
estouro.cpp:8:15: warning: overflow in conversion from ‘int’ to ‘short int’ changes value from ‘70000’ to ‘4464’ [-Woverflow]
    8 |     short d = 70000;
      |               ^~~~~
$ ./estouro
-1294967296 -2147483648 4294967295 4464
  • int a = 3000000000; virou −1294967296 sem aviso com -Wall -Wextra. Só a opção -Wconversion pega: warning: conversion from ‘long int’ to ‘int’ changes value from ‘3000000000’ to ‘-1294967296’ [-Wconversion].
  • INT_MAX + 1 com int é comportamento indefinido. Aqui, como é uma conta feita na compilação, o g++ avisou (-Woverflow); numa conta com variáveis, não avisaria.
  • unsigned c = -1; vale 4294967295, sem aviso: em unsigned as contas "dão a volta" (aritmética módulo 2³²), e isso é definido. Do mesmo jeito, 0u - 1 dá 4294967295.
  • short d = 70000; virou 4464 (70000 − 65536), com aviso.

3. Com chaves, o compilador recusa. A inicialização com {} não aceita conversões que perdem valor (narrowing, "estreitamento"):

int main() {
    int a{3000000000};
    return a;
}

$ g++ -std=c++23 -Wall -Wextra chaves.cpp -o chaves
chaves.cpp: In function ‘int main()’:
chaves.cpp:2:11: error: narrowing conversion of ‘3000000000’ from ‘long int’ to ‘int’ [-Wnarrowing]
    2 |     int a{3000000000};
      |           ^~~~~~~~~~

Um bom motivo para preferir int a{…};. Veja Variáveis e Conversão de Tipos.

4. Divisão de inteiros. 7 / 2 dá 3, e -7 / 2 dá -3 (corta para o lado do zero); -7 % 2 dá -1. Com um dos lados double, 7 / 2.0 dá 3.5. Veja Operadores Aritméticos.

5. Comparar com e sem sinal. -1 < 0u é false: o −1 é convertido para unsigned e vira 4294967295. Por isso o -Wall avisa em i < v.size() com int i (-Wsign-compare).
