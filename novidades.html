C++ Novidades do C++11 ao C++26

Desde 2011, o C++ ganha uma versão nova a cada três anos. Cada uma traz recursos que deixam o código mais curto e mais seguro: o auto, as lambdas, os ponteiros inteligentes, o std::optional, o std::print… Esta página é um mapa: para cada versão, uma tabela com o que mudou, um exemplo mínimo, a aula do guia que ensina o assunto e se o recurso já funciona no g++ 15 e no clang 21. Cada item foi compilado e executado no laboratório.

Você vai aprender
  • Como escolher a versão do C++ na hora de compilar (-std=c++23) e como o programa descobre a versão (__cplusplus).
  • O que cada versão trouxe de mais importante: C++11, C++14, C++17, C++20, C++23 e C++26.
  • Como o mesmo programa fica em C++98 e em C++23.
  • O que do C++26 já funciona no g++ 15 e o que ainda não chegou (reflexão, contratos, std::inplace_vector).
  • Os erros que aparecem quando você usa um recurso novo com a versão errada.

A história completa das versões (quem decide, por que demorou de 1998 a 2011) está em Versões do C++. Aqui o foco é prático: o que você pode usar hoje. Todos os programas foram compilados na máquina fictícia da Ana (usuária ana, computador notebook), na pasta ~/cpp/novidades, com o g++ 15.2 e o clang++ 21.1 do Ubuntu 26.04.

A ideia: atualizações de um celular

Pense no celular da Ana. De tempos em tempos chega uma atualização com recursos novos: um jeito mais fácil de tirar foto, um modo escuro. Os aplicativos antigos continuam funcionando; a atualização só acrescenta coisas.

O C++ é igual. Um programa escrito em 1998 ainda compila hoje, quase sempre sem mudar nada. Cada versão nova acrescenta ferramentas. Mas existe uma diferença importante: no celular, a atualização é instalada uma vez e pronto. No C++, você escolhe a versão toda vez que compila. Se você não escolher, o compilador usa uma versão padrão, que pode ser mais antiga do que você imagina.

1. Escolher a versão: -std=

Quem decide a versão é a opção -std= (de standard, "padrão") do compilador. Você já viu isso em Compilar com g++: o comando padrão do guia é g++ -std=c++23 -Wall -Wextra arquivo.cpp -o programa.

Dentro do programa, a versão aparece num número especial chamado __cplusplus (com dois sublinhados na frente). O compilador o preenche sozinho com o ano e o mês da versão. Este programa só mostra esse número:

#include <iostream>

int main() {
    std::cout << __cplusplus << '\n';
}

A Ana compilou o mesmo arquivo com cada versão, de uma vez só, com um laço for do terminal (Bash). Não se preocupe com o laço: o que importa é a saída.

Repare na última linha. Sem -std=, o g++ 15 compila em C++17. Tudo o que veio no C++20 e no C++23 (std::format, std::print, ranges, contains) fica de fora. É por isso que o guia sempre escreve -std=c++23. No editor do guia, o Rodar já usa -std=c++23.

c++2c, c++2b, gnu++23: outros nomes

Antes de uma versão ter número oficial, os compiladores usam um apelido: c++2b era o C++23 e c++2c é o C++26. O g++ 15 aceita -std=c++26 e -std=c++2c (os dois são a mesma coisa). Já gnu++23 é "C++23 mais as extensões do GNU"; o guia usa sempre o c++23 puro, para o código funcionar em qualquer compilador.

2. C++11: a grande virada C++11

Depois de 13 anos sem novidades grandes, o C++11 mudou o jeito de escrever C++. Quase todo o "C++ moderno" que este guia ensina começa aqui.

Este programa usa todos esses recursos de uma vez. Não se preocupe em entender cada linha agora: cada uma tem a sua aula. A ideia é ver que tudo compila e roda.

#include <iostream>
#include <memory>
#include <string>
#include <utility>
#include <vector>

enum class Cor { vermelho, verde };

constexpr int quadrado(int x) { return x * x; }

int main() {
    auto preco = 4.5;                           // auto
    std::vector<int> notas{7, 9, 10};           // lista entre chaves
    for (int n : notas) std::cout << n << ' ';  // range-for
    std::cout << '\n';
    auto dobro = [](int x) { return x * 2; };   // lambda
    int* p = nullptr;                           // nullptr
    std::unique_ptr<int> u(new int(42));        // smart pointer (C++11)
    std::shared_ptr<int> s = std::make_shared<int>(7);
    std::string a = "lista de compras";
    std::string b = std::move(a);               // move
    constexpr int q = quadrado(5);              // constexpr
    Cor c = Cor::verde;                         // enum class
    std::cout << preco << ' ' << dobro(21) << ' ' << (p == nullptr) << ' '
              << *u << ' ' << *s << ' ' << b << ' ' << q << ' '
              << (c == Cor::verde) << '\n';
}

O 1 depois do 42 é o true de p == nullptr: o cout mostra os booleanos como 1 e 0 (veja Booleanos). O new int(42) da linha do unique_ptr é o jeito do C++11; o C++14 trouxe uma forma melhor, logo abaixo.

O mesmo programa, antes e depois

Para sentir a diferença, veja um programa da lista de compras da Ana escrito como se escrevia em 1998: um mapa de preços, uma lista e o total.

#include <iostream>
#include <map>
#include <string>
#include <vector>

int main() {
    std::map<std::string, double> precos;
    precos["pão"] = 7.5;
    precos["leite"] = 5.25;
    precos["café"] = 18.9;

    std::vector<std::string> lista;
    lista.push_back("café");
    lista.push_back("pão");

    double total = 0;
    for (std::vector<std::string>::const_iterator it = lista.begin(); it != lista.end(); ++it) {
        std::map<std::string, double>::const_iterator p = precos.find(*it);
        if (p != precos.end()) {
            std::cout << p->first << ": " << p->second << "\n";
            total += p->second;
        }
    }
    std::cout << "Total: " << total << "\n";
}

E agora o mesmo programa em C++23:

#include <map>
#include <print>
#include <string>
#include <vector>

int main() {
    const std::map<std::string, double> precos{
        {"pão", 7.5}, {"leite", 5.25}, {"café", 18.9}};
    const std::vector<std::string> lista{"café", "pão"};

    double total = 0;
    for (const auto& item : lista) {
        if (auto p = precos.find(item); p != precos.end()) {
            const auto& [nome, preco] = *p;
            std::println("{}: {}", nome, preco);
            total += preco;
        }
    }
    std::println("Total: {}", total);
}

3. C++14: acabamento C++14

O C++14 foi uma versão pequena, que arredondou o C++11. O item mais importante para você é o std::make_unique: com ele, o new some de vez do código do dia a dia.

4. C++17: ferramentas do dia a dia C++17

O C++17 trouxe "caixinhas" que resolvem problemas comuns: um valor que pode não existir (optional), um valor que pode ser de dois tipos (variant), um texto que você só quer ler (string_view) e um jeito de mexer em pastas e arquivos (filesystem).

std::optional<int> buscar(const std::map<std::string, int>& m, const std::string& k) {
    if (auto it = m.find(k); it != m.end()) return it->second;  // if com inicializador
    return std::nullopt;
}

void saudar(std::string_view nome) { std::cout << "Oi, " << nome << '\n'; }

int main() {
    std::map<std::string, int> estoque{{"maçã", 12}, {"pera", 0}};
    for (const auto& [fruta, qtd] : estoque)              // structured bindings
        std::cout << fruta << ": " << qtd << '\n';
    std::cout << buscar(estoque, "maçã").value_or(-1) << ' '
              << buscar(estoque, "uva").value_or(-1) << '\n';
    std::variant<int, std::string> v = std::string("dez");
    std::cout << std::get<std::string>(v) << '\n';
    saudar("Ana");
    std::cout << std::filesystem::current_path() << '\n';
}

5. C++20: a segunda grande virada C++20

O C++20 é tão grande quanto o C++11. Ele mudou como se escrevem templates (concepts), como se percorrem coleções (ranges), como se formata texto (std::format) e até como se organizam os arquivos (módulos).

#include <ranges>

template <std::integral T>
T dobro(T x) { return x * 2; }

struct Versao {
    int maior, menor;
    auto operator<=>(const Versao&) const = default;
};

int soma(std::span<const int> v) { int t = 0; for (int x : v) t += x; return t; }

int main() {
    std::vector<int> notas{3, 8, 5, 10, 7};
    auto aprovadas = notas | std::views::filter([](int n) { return n >= 6; });
    for (int n : aprovadas) std::cout << n << ' ';

Módulos ainda pedem uma opção extra

No g++ 15, módulos só funcionam com a opção -fmodules, além do -std=c++20 ou mais novo. O CMake e as IDEs ainda estão se acostumando com eles. A aula Módulos mostra o passo a passo; no dia a dia, os #include continuam sendo a forma mais comum.

6. C++23: a versão deste guia C++23

O C++23 completou o que o C++20 começou. O recurso que você mais vai ver no guia é o std::println: escrever na tela com marcadores {}, sem a fila de <<.

import std; no g++ 15

O import std; troca todos os #include da biblioteca padrão por uma linha. No g++ 15 ele funciona, mas a biblioteca precisa ser compilada como módulo na primeira vez. Isso se faz acrescentando o arquivo bits/std.cc (que vem com o g++) ao comando:

import std;

int main() {
    std::println("Olá do import std!");
}

baratos.cpp:8:9: error: conversion from ‘std::ranges::filter_view<std::ranges::ref_view<std::vector<double> >, main()::<lambda(double)> >’ to non-scalar type ‘std::vector<double>’ requested
    7 |     std::vector<double> baratos = precos
      |                                   ~~~~~~
    8 |         | std::views::filter([](double p) { return true; /* troque */ });
      |         ^~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~

O aviso é só porque o p ainda não é usado. O erro, traduzido: "pediram uma conversão de filter_view para std::vector<double>". Um filter é só uma "vista" que escolhe elementos na hora em que você percorre; ele não é um vector. O ranges::to existe exatamente para fazer essa conversão. (O Clang do editor diz a mesma coisa com outras palavras: no viable conversion.)

7. C++26: o que já chegou e o que ainda não C++26

O C++26 é a versão mais nova. O comitê fechou o texto, mas os compiladores ainda estão implementando as partes. As duas novidades mais esperadas são a reflexão (o programa poder "olhar para si mesmo": listar os campos de uma struct, os nomes de um enum) e os contratos (escrever na própria função as condições que os argumentos devem cumprir). A Ana testou cada item com g++ -std=c++26 e clang++ -std=c++2c:

Os dois primeiros erros dizem a mesma coisa: o cabeçalho (<meta> da reflexão, <inplace_vector>) não existe na biblioteca do g++ 15. A parte "Arquivo ou diretório inexistente" sai em português porque vem do sistema, não do g++. No terceiro, o g++ não conhece a palavra pre naquele lugar e se perde: o segundo erro (‘dividir’ was not declared) é só consequência do primeiro. Use C++26 só quando precisar

Como o C++26 ainda está chegando aos compiladores, código com -std=c++26 pode não compilar no computador de outra pessoa. Para projetos, o C++23 (ou até o C++20) é a escolha segura em 2026. O editor do guia também usa -std=c++23.

Quando dá errado

"has no member named ‘contains’": esqueceu o -std= 
#include <iostream>
#include <map>
#include <string>

int main() {
    std::map<std::string, int> estoque{{"maçã", 12}};
    if (estoque.contains("maçã"))
        std::cout << "tem maçã\n";
}

$ g++ -Wall -Wextra contem.cpp -o contem
contem.cpp: In function ‘int main()’:
contem.cpp:7:17: error: ‘class std::map<std::__cxx11::basic_string<char>, int>’ has no member named ‘contains’
    7 |     if (estoque.contains("maçã"))
      |                 ^~~~~~~~

O que significa: "a classe std::map não tem nenhum membro chamado contains". Sem -std=, o g++ 15 compilou em C++17, e o contains só veio no C++20. O tipo comprido (std::__cxx11::basic_string<char>) é só o nome completo de std::string.

Como consertar: acrescente -std=c++23. Sempre que um recurso novo "não existe", desconfie primeiro da versão.

"‘println’ is not a member of ‘std’": versão antiga demais 
$ g++ -std=c++20 -Wall -Wextra imprime.cpp -o imprime

imprime.cpp:4:10: error: ‘println’ is not a member of ‘std’

O que significa: "println não é membro de std". Aqui o g++ ajuda: a nota da última linha diz que std::println só existe "do C++23 em diante". O #include <print> não deu erro, mas, em C++20, o arquivo existe vazio.

Como consertar: -std=c++23, como na segunda tentativa.

Código moderno num compilador configurado para C++98 
$ g++ -std=c++98 -Wall -Wextra compras23.cpp -o x
compras23.cpp: In function ‘int main()’:
compras23.cpp:7:47: warning: extended initializer lists only available with ‘-std=c++11’ or ‘-std=gnu++11’ [-Wc++11-extensions]
    7 |     const std::map<std::string, double> precos{
      |                                               ^
compras23.cpp:7:41: error: in C++98 ‘precos’ must be initialized by constructor, not by ‘{...}’

O que significa: o aviso diz que "listas de inicialização estendidas" (as chaves {…}) só existem a partir do C++11, e o erro diz que, em C++98, o mapa teria de ser preenchido de outro jeito. Essa saída continua por dezenas de linhas, uma para cada recurso moderno do arquivo; só as primeiras aparecem aqui.

Como consertar: isso acontece com projetos antigos (um Makefile com -std=c++98) ou IDEs mal configuradas. Troque a opção para -std=c++23. Veja onde ela fica em Make e CMake.

"fatal error: …: Arquivo ou diretório inexistente" com um cabeçalho novo

Você viu esse erro na seção do C++26, com <meta> e <inplace_vector>. Ele quer dizer que o cabeçalho não existe na biblioteca do seu compilador: ou o recurso é novo demais, ou o nome está errado (<vetor>, <strings>). Confira o nome; se estiver certo, o seu compilador ainda não tem o recurso.

Resumo

  • Uma versão nova a cada três anos: C++11, 14, 17, 20, 23 e 26. O código antigo continua compilando.
  • Você escolhe a versão com -std=. Sem ela, o g++ 15 usa o C++17. O guia usa sempre -std=c++23.
  • C++11 e C++20 foram as grandes viradas; C++14 e C++23 completaram o que elas começaram; C++17 trouxe optional, variant e companhia.
  • Tudo do C++23 que o guia ensina funciona no g++ 15 e no clang 21. import std; funciona no g++ 15 com -fmodules e bits/std.cc.
  • Do C++26, os recursos menores já funcionam; reflexão, contratos e std::inplace_vector ainda não estão no g++ 15 nem no clang 21.
  • "Não é membro", "não existe" ou "fatal error: … inexistente" com um recurso novo: confira primeiro o -std=.
